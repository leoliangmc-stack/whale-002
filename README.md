# 鲸落：深海之境 · Whale Fall: The Living Abyss

以鲸落生态为主题的 2.5D 沉浸式网页互动体验。用户通过滚动 / 滑动推进一段首尾相接的循环叙事：一头 24 米长的蓝鲸滤食磷虾 → 浮上海面呼吸 → 眼睛缓缓闭上 → 沉入深海 → 落在海床 → 身体逐渐分解 → 鲸骨成为生命岛屿 → 磷虾重新聚集 → 新的鲸鱼从远处游来，并无缝回到开场。完成一圈后解锁“自由探索”，可以拖动、缩放、点击观察鲸骨周围的生态群落。

- 支持 PC、iPad、手机浏览器（Chrome / Safari / Edge，iOS / iPadOS Safari）
- 蓝鲸与鲸骨是 whale-kit 中的水彩画（约 0.8 MB WebP），沿脊线切成条带实时弯曲、张嘴、下沉与分解；其余画面为程序实时生成，保留了正式资源的替换接口
- 全程有声音，全部来自真实录音（见「声音」）：蓝鲸的歌声与远处的鲸群合唱是 MBARI 的水听器录音（加速 6 倍后可听），水下环境、气泡、枪虾与抹香鲸来自 NOAA / 美国海军 SanctSound 水听器，海浪、溅水、呼吸等来自 ESC-50 中单独标为 CC0 / CC BY 的实地录音；按声音导演的剪辑表（`docs/sound/cue-sheet.md`）随画面与旁白混音，47 个 MP3 共约 2.4 MB，按段落分批加载
- 旁白（可开关，默认打开）：一位知性女声朗读每一条字幕，由开源的本地语音合成模型 Kokoro-82M v1.1-zh（Apache-2.0）生成，22 段共约 0.9 MB（见「旁白」）；说话时环境声与音效自动压低
- 生产包约 285 KB JS（gzip 后约 106 KB），另加 `assets/whale/` 中的绘画、`assets/audio/` 中的录音与 `assets/narration/` 中的旁白

**在线体验：** https://leoliangmc-stack.github.io/whale-002/

## 1. 运行与构建

需要 Node.js 18+。

```bash
npm install          # 安装依赖（Vite、TypeScript、Vitest）
npm run dev          # 开发服务器（默认 http://localhost:5173，--host 可供局域网手机 / iPad 访问）
npm run build        # 类型检查 + 生产构建，输出到 dist/
npm run preview      # 预览生产构建
npm test             # 单元测试（Vitest，116 项）
```

`dist/` 是纯静态文件，可直接部署到任意静态托管（构建使用相对路径 `base: './'`，放在子目录中也能运行）。

### 部署到 GitHub Pages

每次推送到 `main`，`.github/workflows/deploy-pages.yml` 会自动执行：安装依赖 → 运行单元测试 → 构建 → 把 `dist/` 发布到 `gh-pages` 分支，GitHub Pages 再从该分支上线（仓库 Settings → Pages 的来源为 `gh-pages` 分支、根目录）。测试不通过时不会发布。也可以在 Actions 页面手动运行这个工作流。

滚动距离按镜头分配：开场的五个镜头每个约对应一屏高度的滚动，用户可以在任何一个镜头上停下来慢慢看；其余段落一整圈约 34 屏。

## 3. 技术方案

**TypeScript + Vite + 原生 Canvas 2D**，无运行时依赖。

### 关于没有采用 Phaser 3（与需求文档推荐技术栈的差异）

需求文档推荐 Phaser 3，同时要求“遇到技术选择时优先选择稳定、可维护的实现，不要引入不必要的复杂框架”。评估后选择了原生 Canvas 2D：

1. **画面以程序化绘制为主**（可弯曲的鲸鱼身体、张嘴鼓喉、渐进分解、骨骼坍塌都是对绘画或矢量路径的实时变形）。Phaser 的 Graphics 对象不支持任意路径的线性 / 径向渐变，而这些正是体积感与水下光照的基础；若改用 CanvasTexture 每帧重绘再上传 GPU，在手机上反而更慢。
2. **叙事由滚动进度驱动，而不是游戏循环**：所有状态是进度的纯函数，Phaser 的场景 / 物理 / Tween 体系基本用不上。
3. 体积更小：整个项目的代码约 255 KB（gzip 后约 94 KB），而 Phaser 3 的完整构建本身就约 1 MB（未压缩），首屏更快。

模块划分仍然沿用了文档中的 12 个模块（见下表），如果未来需要 WebGL 或 Three.js，只需替换渲染层。

### 核心设计

- **统一的进度系统**：完整叙事映射为 `storyProgress ∈ [0,1)`。镜头、鲸鱼、磷虾、光照、粒子、生物数量、骨骼状态全部由同一套关键帧轨道（`core/Track.ts`，单调三次插值，不过冲）从进度求值，任何模块都不单独监听滚动事件。因此正放、倒放、重播得到完全一致的画面。
- **关键镜头保护**：显示进度以受限速度追赶目标进度；关键镜头段（开场五镜头、滤食、喷气、闭眼、着陆、分解、新鲸鱼……）的最高速度更低，快速滚动会“快放”经过，而不会直接跳过。每一段还可以单独指定滚动长度（`Segment.screens`），换算由 `StoryProgressController.advance()` 逐段完成，可以正反向跨圈。
- **无缝循环**：镜头是循环轨道（在 p=1 与 p=0 处 C1 连续）；新鲸鱼与开场鲸鱼共用同一条“鲸鱼谱系”轨道（`u = p − 1`），磷虾群同理，所以位置、大小、朝向、速度、姿态、海水颜色在衔接处天然一致。单元测试逐项校验横屏与竖屏两种构图下的衔接。
- **真正的 2.5D**：带镜头平移（lens shift）的透视相机，所有对象都有深度 z，背景山脊、岩石、海床、生物、颗粒按真实透视产生视差；水体雾化按深度与距离计算。
- **鲸鱼**：一头 24 米长的蓝鲸。几何是脊线 + 背腹剖面的可变形模型（剖面从绘画的轮廓量出，`entities/WhaleBody.ts`），画面是 whale-kit 的水彩画（`entities/WhaleArt.ts`）：沿体轴切成约 0.3 米宽的条带，每条按脊线的位置与方向摆放，所以身体能随尾叶上下摆动、下沉时弯曲、静卧时贴合海床；体轴上下两半可以分别缩放（喉囊鼓起、分解时软组织收缩）。滤食时张嘴的画（约 30°）按当前的张角连续变形：颌关节以下的扇形（下颌与喉囊）与以上的扇形（吻部）分别按分块仿射变形——张得更大时下颌继续下转到约 90°（须鲸冲刺滤食时上下颌张角接近 90°），喉囊沿半径方向鼓起；张得更小时下颌往上合、画中微微抬起的吻部绕颌关节放下来，合拢时与游动的画重合，所以两张画只在嘴几乎闭上的一瞬间交接，张嘴与闭嘴都看不出换画；上下颌之间的缝隙保持透明。下沉时身体可以绕体轴翻过来（`WhaleBody.rolledHeight`）：把横截面看成近似的椭圆，转动途中每条带沿横截面分块、按转动后的高度重新排布，越过腹中线后用画上下翻过来代替远侧的一面（左右对称），并按转动后平滑的轮廓裁剪；肚子朝上时整幅画沿体轴翻转。眼睛特写与闭眼使用两张高分辨率的眼睛画（预处理中把夕阳暖光改为水下冷光、与身体画对色），眼睑从睁眼的画扫到闭眼的画。画面在离屏图层中按深度着色（与程序绘制的物体同一个光照模型），远处的鲸鱼使用预先缩小的版本，分解时挖出边缘柔和的空洞，露出同一条脊线上的骨骼。
- **游动动作**（`systems/SwimMotion.ts`）：开场到滤食同样是在故事时间上积分一次的确定性动作表：几次缓慢有力的拍尾（约 0.14–0.22 Hz，上拍比回程快，每一次的幅度与频率略有不同）与短暂的滑行交替；推力（幅度² × 频率²）减去阻力驱动速度的缓慢起伏，拍尾时略微加速、滑行时略微减速；路径的关键帧按秒插值，镜头段之间没有速度突变；俯仰跟随路径方向并略微领先（身体先转、路径随后），先保持深度、再以约 12° 平缓下潜、在磷虾群前放平；冲刺滤食前加快拍尾，张嘴后停止拍尾、靠惯性滑行减速。胸鳍、尾柄与头部是被动层：滑行时胸鳍微微张开，转向、上浮时调整角度，用力拍尾时贴近身体。拍尾相位由故事时间决定（两头鲸鱼共用，循环衔接处一致），用户停下时叠加一个缓慢的悬停轻摆。身体经过时推开附近的海洋雪，尾叶每次拍动都把身边的颗粒推开一点并带起小小的旋涡。叙事镜头的关键帧也按故事时间插值，推拉与平移的速度在段边界处连续，镜头跟随点在加速、减速与调整深度时稍稍滞后。
- **下沉动作**（`systems/DescentMotion.ts`）：从最后几次摆尾到落上海床是一段确定性的物理模拟——推力、浮力变化、二次阻力、头重力矩、水流与海床接触——在“故事时间”（自动播放的秒数）上积分一次并制成查找表，查表只依赖进度，因此暂停、倒放、跳转都得到同一姿态。尾柄、尾叶与头部是由二阶阻尼跟随驱动的被动层，惯性与滞后各不相同；失去肌张力之后，头部先沉，身体一边下沉一边在约 35 秒里缓缓翻过来、变成肚子朝上（参考画面），之后一直保持肚子朝上，背部先触底、肚子朝上躺在海床上，同时转成约 43° 的低头姿态，从浮力最大的胸腹部“挂”成一道弓形：前半身几乎笔直地斜向下方，背部在体长约七成处拱起，尾柄顺着长弧垂下，尾端斜向下方约 34°（转角场从参考画面中量出，沿脊线按弧长积分，体长不变，`WhaleBody.archAngle`）；下沉时自下而上的水流把尾叶托向尾柄的延长线；两侧胸鳍是以肩关节为铰链的被动硬桨（见下文「胸鳍与尾叶的物理」），被相对水流托离身体、不停地轻轻摆动，下沉放缓时回到画中的姿态；低垂的头部带着身体向前滑一点，斜斜地、缓慢安静地沉向深海。俯仰由“拉向目标角度的力矩 + 阻尼”积分得到，带着惯性与滞后，不是直接设定的角度。镜头跟随点也带有同样的质量感（匀速时不落后，起动、减速时才滞后）。
- **水体参照系**：1800 米的下沉被艺术化压缩，但鲸鱼相对周围海水的可见下沉只有约 2.3 m/s（同时向前滑行约 0.75 m/s）。海洋雪、途中相遇的少数生物与海床都锚定在水体参照系中，被压缩的深度由镜头与鲸鱼一起整体带走；深度计、水色与光照仍按真实深度变化。鲸鱼经过时，附近的颗粒会被轻轻推开、身后的颗粒被稍稍带走。
- **鲸骨**：whale-kit 中与身体画同一取景的骨骼画，按同一条脊线切成更细的条带，分解时从空洞里露出的骨头与身体严格对齐。鲸落肚子朝上，骨骼画与身体画一样沿体轴上下翻转：脊柱贴着海床，肋骨朝上，头骨倒扣着、下颌骨在上方。坍塌时整副骨架朝海床压低（朝上的肋骨摊开、变矮，头骨只略微下沉），条带之间用剪切保持脊柱连续；沉积物把骨头染成灰褐色。细菌席与食骨蠕虫长在骨头朝上的表面上（翻转之后是画中骨头的下缘），这些位置是从骨骼画的透明度中找出来的；自由探索中的点击会换算回画中的像素，按分区判断是头骨、下颌骨、椎骨、肋骨、肩胛骨、胸鳍骨还是退化的骨盆。

## 4. 目录结构与关键模块

```

                             食腐动物的伤口时间表（feast.ts）
  controllers/               StoryProgressController、CameraController、InputController、ResponsiveLayoutManager
  core/                      数学与噪声、关键帧轨道、透视相机、颜色 / 着色、程序化纹理、本地存储
  entities/                  Whale / WhaleBody / WhaleSkeleton / WhaleArt（蓝鲸绘画与锚点）、FinGeometry（下沉时胸鳍的三维姿态）、

  scenes/                    World（共享世界）、NarrativeScene（模式 A）、ExploreScene（模式 B）
```

### 开场五镜头（阶段 1 前半段）

开场先建立鲸鱼的体型、力量与安宁，再进入捕食。五个镜头是同一条连续的机位运动（推、跟、升降、对焦转移），没有跳切；配置见 `config/stages.ts` 的 `OPENING_SHOTS` 与 `systems/StoryTimeline.ts` 的 `CAM_ROWS`。

| 进度 | 镜头 | 自动播放 | 画面 |
|---|---|---|---|
| 0.000–0.014 | 超远景建立尺度 | 5 秒 | 辽阔的蓝色海水、柔和的光束与漂浮颗粒，鲸鱼从远处的雾蓝中缓缓游来，在画面中只占很小的比例 |
| 0.014–0.030 | 侧面全景跟拍 | 5 秒 | 机位与鲸鱼平行移动，完整呈现头部、身体、胸鳍与尾鳍；尾叶慢速摆动，身体随之起伏 |
| 0.030–0.047 | 低角度仰拍 | 5 秒 | 机位缓缓沉到鲸鱼下方，庞大的身体从画面上方经过；明亮的海面天光从上方透下，身体逆光变暗，背部边缘被勾出柔和光边 |
| 0.047–0.061 | 侧面中景 | 5 秒 | 镜头升回与鲸鱼相近的高度，沿身体向头部缓缓平移：头部、胸鳍与前半身在画面中，不推近到眼睛（眼睛的特写留给之后“眼睛缓缓闭上”）；第一只橙红色的磷虾从头前漂过 |
| 0.061–0.075 | 磷虾群揭示 | 5.5 秒 | 先是零星几只，再缓缓拉远，前方的磷虾越聚越多，聚成成千上万只小虾组成的密集虾团；鲸鱼放平身体、慢慢转向虾群（竖屏下构图沿对角线转向） |

动作原则：鲸鱼的速度、转向角速度和镜头的推拉速度都有上限（单元测试校验：游速 < 9.4 m/s（约 0.4 倍体长每秒）、转向 < 0.1 rad/s、景别变化 < 40%/s、开场全程不张嘴）；尾叶摆动频率约 0.14–0.22 Hz（蓝鲸是拍尾最慢的须鲸），上百吨的身体几乎不随尾叶上下起伏（近景中头部的起伏只有几厘米），体现大型动物的重量与惯性。动作有节奏：侧面跟拍里是一次完整有力的拍尾，仰拍时庞大的身体停止拍尾、胸鳍微张，静静地从上方滑过，侧面中景里恢复拍尾，看见磷虾群之前已经放平身体，随后加快拍尾、保持深度径直冲向虾群（`tests/swim.test.ts` 逐项校验：拍尾与滑行交替、频率不恒定、速度在时间上连续且滑行时减速、俯仰与路径方向一致、胸鳍角度变化且张嘴时回到原位、镜头滞后有界、交还关键帧处连续）。开场只有两声远处传来的蓝鲸歌声（真实录音）与近景里拍尾推开海水的闷响。

**从侧面中景到滤食是一条平稳、单向的机位运动**（`tests/feeding.test.ts` 校验）：镜头只跟随鲸鱼（不再在鲸鱼与虾群之间来回混合），磷虾群出现时一次性拉远到约 26 米的景别并保持，鲸鱼在画面中只朝一个方向缓缓移动、上下位置几乎不变（19–38 秒内变化小于画面高度的 5%）；鲸鱼在磷虾群出现之前已经放平，冲刺与张嘴时保持深度，不会一会儿低头、一会儿抬头。光束的亮度只有很慢、很轻的起伏，数量与位置不随画质分级变化；画质自动升降时磷虾与海洋雪在一两秒内逐渐增减，恢复一次之后再降级就不再恢复，画面不会忽明忽暗。

**磷虾被吸进嘴里**：时间线把虾团对准张开的嘴（群体中心放到嘴的前进方向上，长轴与体轴一致，鲸鱼径直冲进虾团）。只有离这条轴线约 3.4 米以内、正好在张开的嘴的范围内的磷虾会被吞下：涌进嘴里的水流先把它们向轴线收拢（喇叭口），再越来越快地把它们吸进嘴里，被拉成细长的一道；正对着嘴的几层虾群斑点随之收拢、拉长、被吸进去。嘴的范围之外的磷虾被头部推开的水流带到身体两侧（不会穿过身体），随后散开。

### 下沉：从停止游动到落上海床（阶段 3 末 ~ 阶段 5）

| 0.497–0.518 | 着陆 | 约 6 秒 | 以约 0.25 m/s 接触海床（胸鳍与身体的弧度此前已回到静卧的姿态）：肚子朝上，宽阔的背部先触底、在约 2 秒内再压进软泥约 0.3 米；头骨随后放低；尾柄最后落下，尾叶触底时有一次约 6 厘米、很快消失的下压。大团细沉积物沿身体依次被挤出、向上翻涌到约 5 米高，贴着海床向两侧涌出，鲸鱼身后扬起一层宽阔的尘雾，约 12 秒后沉降完毕 |

**胸鳍与尾叶的物理**（`entities/FinGeometry.ts`、`DescentMotion` 的 `FinSim`）：须鲸的胸鳍几乎是一块硬桨——肘关节被肱骨远端的骨脊锁死，指间关节几乎不能动，能转动的主要是肩关节（腕部只剩很小的屈伸）。生命结束后肌肉不再出力，胸鳍就是一块以肩关节为铰链的被动平板，像风向标一样被水动力转向相对水流的方向：两侧胸鳍各有一个三维方向（沿体轴、垂直于体轴、朝向镜头），目标方向是相对水流的方向加上一点离开体侧的偏置；水流把它推向身体时被体侧挡住，贴着体侧顺向后方；水流越弱越接近画中的自然姿态（水流速度约 0.6 m/s 时两者各占一半）。在这个目标上叠加缓慢的水流扰动与涡旋脱落引起的约 0.55 Hz 的轻微颤动，三个分量各自做二阶阻尼跟随，得到惯性与滞后。于是：死后向前滑行时，胸鳍顺着水流贴向体侧、指向后方；开始下沉后水流转为自下而上，翻身途中鳍根随横截面转到侧面、再转到上方，胸鳍被托离身体；肚子朝上低头下沉时（海水从吻端流向尾部、同时自下而上流过，相对水流与体轴约成 20°–30°），两侧胸鳍斜向后上方伸出身体轮廓，并不停地轻轻摆动；接近海床、下沉放缓时回到画中的姿态，着地后与之后露出的鳍骨一致。绘制时胸鳍是从画中切出来的单独图层：鳍根放在翻身之后横截面上的位置，按三维方向在侧视中的投影摆放（朝向或背离镜头时变短），鳍根转到背向镜头一侧的那只先画、被身体挡住，只露出伸出轮廓的部分。尾柄与尾叶同样被自下而上的水流托向尾柄的延长线，比尾柄更软，随尾柄的运动反向滞后。尾叶是一块水平的薄板：侧面看是画中的样子，翻到一半时正对镜头，看到的是两片叶左右对称展开的整个尾叶——用画中的尾叶与它上下翻过来的样子交叉叠加并按翼展拉开来近似（之前翻身途中尾叶会被裁掉，已修正）。

动作原则（单元测试 `tests/descent.test.ts` 逐项校验）：摆尾幅度单调减小、频率降低；摆尾停止后至少 4 秒才开始明显下沉；头部先沉 1.7 米时尾部的高度变化小于 0.5 米（按弯曲之后的实际位置），转成低头姿态用时超过 11 秒；下沉加速度不超过 0.51 m/s²，速度在约 2.3 m/s 处趋于平稳、不会无休止地加速，并且向前滑一点（运动方向偏离竖直方向 10°–30°）；俯仰角速度小于 0.09 rad/s，没有持续摇晃；翻身最快约 10°/s、用时 28 秒以上，之后一直肚子朝上直到静卧；镜头最多略低于鲸鱼 3 米，不会沉到它下方去仰拍，下沉途中鲸鱼在画面中的上下位置变化小于画面高度的 8%；稳定下沉时的姿态与参考画面一致（胸部 38°–47°、头部 42°–52° 低头，尾端斜向下方 26°–44°，背部最高处在体长的六成到八成之间），弯曲保持体长、任意 1 米内方向变化小于 10°；胸鳍是单位方向向量、始终在体表之外（不会穿进身体），翻身之前贴着体侧顺向后方，肚子朝上下沉时被托离身体（斜向后上方 11°–54°）并不停地轻轻摆动，相邻 0.1 秒内方向变化很小，开始与结束时与画中的姿态一致；光束在约 1000 米之前消失；触底时刻、静卧姿态与交接处的位置和速度连续；任意顺序求值结果一致。

### 静卧在海床上（阶段 5 之后）

静卧姿态由 `entities/WhaleBody.ts` 的 `restSpineDY` / `restRoll` 给出，接触关系由 `entities/Whale.ts` 的 `updateContact` / `drawContact` / `drawBerm` 绘制，单元测试 `tests/rest.test.ts` 逐项校验：

- **肚子朝上**：下沉途中翻过来的身体不再翻回，肚子朝上躺在海床上；画面沿体轴上下翻转，轮廓的上缘是腹部，着地的是背侧的轮廓。
- **重量**：宽阔的背部压入沉积物约 0.3 米；沉重的头骨在颈部附近以长弧线放低，头顶贴着海床，吻端尖自然地微微翘起；尾柄顺着一道越来越弯的弧线垂下、以背脊着地，尾叶顺势落在海床上；很小的背鳍压进软泥里。弯曲沿脊线保持每一段的长度（体长不变），任意 1 米内方向变化小于 10°，没有压扁、拉长或折角。身体略向镜头一侧侧倾（头部约 13°、尾柄约 3°；只影响接触与压痕，绘画本身不旋转）。
- **鳍与尾叶**：画中的胸鳍保持自然的姿态，从朝上的腹侧斜向后上方伸进水里（之后露出的鳍骨与它一致），不会插进海床。尾叶按画中的形状受海床软约束：翻过来之后的叶尖接近海床时就被缓缓托起，可以略微陷进软泥，但不会插进海床。
- **接触关系**：按每一段身体实际离海床的高度绘制分区域的软阴影（压入处最深、尾柄与下颌下方较淡较宽，胸鳍与尾叶在落地处各有一小片），另有一层很宽、很淡的环境遮蔽；压入沉积物的部分被近侧隆起的软泥边缘挡住（按透视投影到侧视平面裁剪），边缘有柔和的亮边、暗坡与零星泥块；身体下缘只在接触处加深，没有一圈均匀的黑边。海床上的印痕按未分解的完整身体计算，分解与骨骼阶段依然保留。
- **镜头与光**：着陆后缓慢推近为斜侧面中远景，镜头略高于海床，构图中心在吻端与尾叶之间，头尾完整留在画面内（横屏、竖屏均如此）；深海中加入来自上方的柔和散射光与很克制的冷色轮廓光。

### 鲸落上的进食（阶段 6）

移动食腐阶段发生在海床上：鲸鱼沉到海底之后，几天之内盲鳗、睡鲨、长尾鳕与成群的端足类循着气味赶来，每天能吃掉几十公斤软组织。在海面附近或下沉途中都没有进食（这头鲸鱼一直沉到 1800 米的海床），所以伤口只出现在海床上。

- **伤口时间表**（`config/feast.ts`）：三次睡鲨的撕咬与八个盲鳗钻开的小洞，每一处都给出出现的进度与身体上的位置（沿体轴 s 与离体轴的相对高度 v，肚子朝上时上方是柔软的腹部与喉腹褶）。鲸鱼的伤口绘制（`Whale.drawWounds`）与食腐动物的动作（`systems/Feast.ts`）读同一张表，所以伤口正好在咬下去的那一刻出现；后来的撕咬放在身体中段，因为那时尾部与头部的软组织已经被吃空（单元测试校验每一口都咬在还有肉的地方）。
- **伤口**：不规则、边缘参差、沿体轴拉长的轮廓，外面一圈淤青与白色的鲸脂层，里面是越深越暗的暗红肌肉与几道纤维和裂缝；睡鲨的一口在上缘留下一排扇贝形的齿痕。伤口随后被盲鳗与端足类沿边缘继续啃大。分解的空洞挖掉之前先铺上生肉与鲸脂，挖掉之后留下一圈撕开的边缘；空洞由几块柔和的圆斑拼成，形状不规则。颜色画在身体画上，与身体一起按深度着色。
- **睡鲨**（`Feast.sharkBody`）：圆筒形的粗壮身体、短而圆的吻、嘴在吻部下方、小眼睛、两个很小的背鳍靠后、没有臀鳍、尾鳍下叶较发达，体色是带斑驳的暗灰褐色。动作全部由叙事进度决定：从幽暗中慢慢游来（不超过约 2 m/s）、最后几米放慢、张嘴露出细小的牙、咬住伤口；咬住的约 4.5 秒里扭转身体（绕体轴转动，背鳍与尾鳍随之变矮、较浅的腹部转到侧面）、甩头、向后拉扯——研究者在鲸落上观察到的正是这种“咬住之后扭转身体、一点一点把肉撕下来”的动作；松口后叼着一块肉（暗红的肌肉连着白色的鲸脂）向后退开、慢慢吞下，再转身游回黑暗。
- **盲鳗**：把头钻进伤口刮食，身体在伤口外不停扭动，每隔十几秒把身体打成一个结借力撕扯；数量随伤口的时间增加，伤口处的肉被吃光（分解空洞）时离开。
- **端足类**：约 1.5 厘米的小身体成群覆盖在伤口边缘与周围的体表上，不停爬动。
- 四处游动、循着气味赶来的食腐动物（`CreatureManager` 中的盲鳗、睡鲨、长尾鳕、端足类群与深海蟹）照旧在远处与海床上活动。

### 鲸骨的特写（阶段 7）

镜头依次停在三处骨骼：尾部的一串椎骨（约 0.716–0.739）、朝上摊开的肋骨（约 0.746–0.762）、倒扣的头骨与下颌骨（约 0.769–0.783），区间导出为 `config/stages.ts` 的 `BONE_CLOSEUPS`（声音系统据此放骨面上的细碎声响）。近看时食骨蠕虫（Osedax）是从骨头里伸出的半透明躯干，顶端一簇四条红色的羽状鳃，两侧有细小的羽枝，随水流一起摆动，一个附着点上是一小片密集的群落；细菌席是边缘柔和、带斑驳与丝状绒毛的白、黄、橙色薄膜；每处特写里都有几只啃食细菌席的螺与蹲守的铠甲虾。屏幕之外的附着点不画，特写时的开销与远景相当。

## 6. 正式资源的替换接口

- 在 `public/assets/manifest.json` 中登记纹理与音频即可覆盖程序化资源，例如：
  ```json
  {
    "textures": { "krill": "sprites/krill.png", "caustic": "fx/caustic.png", "mist": "fx/mist.png" },
    "audio": { "whaleAB": "audio/blue-whale-ab.mp3", "chorus": "audio/ocean-chorus.mp3", "spout": "audio/spout.mp3" }
  }
  ```
  纹理键见 `core/textures.ts` 的 `TextureSet`；音频键见 `AudioManager.overrides`：`whaleAB` / `whaleAB2` / `whaleB`（蓝鲸的歌声）、`chorus`（循环的远处合唱）、可选的 `spout`（喷气）。
- 鲸鱼、鲸骨、生物都通过 `prepare()` / `draw(rc)` 接口绘制，可以整体替换为其他实现，而不影响叙事时间线、镜头与生态系统。

### 蓝鲸绘画资源（`public/assets/whale/`）

来自 whale-kit（同一位作者的另一个 Whale Fall 项目，导出于 2026-10-22/23）：六张画由 libtv（General image Pro）按文字提示生成，没有使用任何现有作品作为输入，并经所有者确认；**商用前请先核对 libtv 的输出条款**。在本项目中做了以下处理（原画不在仓库中）：

- `swim` / `lunge` / `skeleton`：三张同一取景的侧视画裁切到同一画框（2870 × 640），清除背景上零星的半透明杂点，保留透明像素下的颜色（避免缩放时出现浅色描边）；锚点（吻端尖、尾叶缺刻、眼睛）见 `entities/WhaleArt.ts`。原画按 14 米标定，这里按 24 米使用。
- `eye-open` / `eye-closed`：缩到 1024 像素，按 kit 中 `relightDaylight()` 的公式把夕阳暖光改为水下冷色顶光，按身体画在眼睛周围的颜色做逐通道校色，并羽化边缘，只保留可能看到的横条。
- `swim-fin-under`：游动的画中胸鳍下面的身体（约 17 KB），由 `python3 scripts/fin-cutout.py` 按 `WhaleArt.ts` 中的胸鳍轮廓 `FIN_POLY` 生成：轮廓外的皮肤作边界做调和填充，再叠加沿体轴方向复制的喉腹褶细节，腹部下缘逐列插值保持清晰。加载时（`WhaleArt.ts` 的 `cutFin`）把轮廓内的原画切成单独的胸鳍图层，轮廓内的身体换成这张补丁；两层按原位叠放时与原画一致。修改轮廓后需要重新运行脚本。
- `dorsal`：俯视的背面画（约 260 KB），由 `python3 scripts/dorsal-art.py <whale-kit/images/web/whale-below.webp>` 生成：whale-kit 中从正下方看的腹面画只提供轮廓（俯视与仰视的轮廓相同），轮廓内画上背部——俯视中离脊线的相对距离对应侧视画中体轴上方的高度，取游动画中相应位置的皮肤，左右两侧沿体轴错开取画（斑纹不会左右镜像），再加顶光的明暗、胸鳍与尾叶的皮肤、很淡的喷气孔、防溅脊与背鳍。锚点见 `WhaleArt.ts` 的 `DORSAL_ART`。
- 身体与张嘴画的轮廓（`WhaleBody.ts` 的 `UPPER` / `LOWER` / `LUNGE_UP` / `LUNGE_LO`）、胸鳍与尾叶的位置、骨骼画的分区都是从画中量出来的；换成另一套同一取景的画时，需要同步更新这些数据。

### 声音（`public/assets/audio/`）

声音按声音导演的剪辑表 [`docs/sound/cue-sheet.md`](docs/sound/cue-sheet.md) 制作，素材的来源、许可与评估见 [`docs/sound/sources.md`](docs/sound/sources.md)，离线混音的测量结果见 [`docs/sound/mix-report.md`](docs/sound/mix-report.md)。

- **全部是真实录音**：水听器录音与实地录音，只做过滤波、变速（变调）、拼接、包络、相位声码器移调与离线的短混响；运行时不合成任何叙事声音、不用卷积混响，素材没加载好时那个声音直接缺席（唯一的合成声音是“新发现”的界面提示音）。
- **视角**：镜头在水下只听见水下的声音，在空中只听见空气中的声音，水线中景两者兼有；出水、入水与画面的水线对齐。深度越深，水下的声音越闷。
- **旁白**：说话时环境声 −7 dB（空气中的海浪 −9 dB）、普通音效 −5 dB、主角音效 −2 dB；鲸鸣排在旁白的空档里，等人声结束 0.5 秒后再唱。
- **确定性**：连续层的电平是叙事进度与相机深度的纯函数（正放、倒放、跳转得到同一状态），一次性音效只在正向经过时触发，快速滚动时只留主角音效，循环接缝不丢、不重复 cue。
- **体积**：47 个 MP3 共约 2.4 MB，按段落分 5 批加载（开场、海面、深海、海床），离开段落后释放解码数据。

`python3 -I scripts/sound-build.py` 从固定的地址下载原始录音并重新生成全部文件与 manifest。

### 旁白（`public/assets/narration/`）

一位知性、沉稳的女声朗读每一条字幕（字幕的 text 与 sub 都读，中间自然停顿）。控制栏、开场界面与设置里都有“旁白”开关（键盘 N），默认打开，偏好保存在本地。

- **生成**：开源的本地语音合成模型 Kokoro-82M v1.1-zh，用 sherpa-onnx 在 CPU 上运行，音色 zf_094（从 55 个中文女声中按基频、起伏、干净程度与识别准确率选出）。没有调用任何付费服务。模型权重 Apache-2.0；训练数据的说明请以模型卡为准（生成环境访问不了 Hugging Face，未能当场核对）。`python3 scripts/narration-tts.py` 可以重新生成，规范化（“24 米”读“二十四米”等）、多音字与变调的修正、逐条的语音识别回听结果见 [`docs/narration.md`](docs/narration.md)。
- **规格**：每条一个 MP3（单声道 24 kHz，64 kbps，−18 LUFS），22 条共约 0.9 MB、110 秒；第一次打开旁白（且声音已解锁）时才下载。
- **播放**（`systems/Narration.ts`）：故事正向播放、进入一条新字幕时开始朗读；从字幕中途进入（跳章节、快速滚动经过）时，只在还没过去一半的情况下才读；暂停时停在原处、继续播放时从停下的地方接着读；倒放与跳转时立即停止；上一条还没读完时下一条排队，等得太久就跳过。说话时把环境声压低 7 dB、普通音效压低 5 dB（见上文「声音」），鲸鸣排在旁白的空档里。
- **与画面对齐**：几条字幕的起点为旁白挪后了一点——喷气最响的部分过去之后才说“温暖的呼气……”（“噗——”由真实的喷气声承担，旁白不读），着地的闷响之后才说“经过漫长的下沉……”，第三次撕咬结束之后才说“富含养分的沉积物里……”；第一句的显示时间按朗读长度放宽。

## 7. 性能与无障碍

- 三档画质（磷虾数量与虾团的密集小点层数、颗粒、光束、焦散、沉积物、像素比上限）；手机默认中档。`PerformanceMonitor` 在持续掉帧时自动降级，长时间流畅时尝试恢复。
- 海水渐变、天光、层层叠叠的光束与参考画面上缘的海面波光都很柔和，合在同一张 1/4 分辨率的离屏图层上绘制（每排波光是一次按纹理坐标缩放的平铺填充），再一次性放大铺满画面，几乎没有全屏填充的开销。
- 粒子与磷虾使用固定数组，运行中不创建 / 销毁对象；鲸鱼只在所在的包围盒区域内用离屏图层合成，深度着色合并为一次填充，远处的鲸鱼使用预先缩小的绘画。
- 页面进入后台时停止渲染并挂起音频。
- 减少动态效果：关闭镜头漂移，降低生物、磷虾与颗粒的运动幅度（默认跟随系统设置，可在设置中切换）。
- 无高频闪烁：生物发光与阳光碎金都是缓慢的亮度变化；快速上升时海洋雪自动降低亮度。
- 所有关键按钮同时有图标与文字标签、`aria-label`、键盘焦点样式，触控区域不小于 44px；字幕与章节有 `aria-live`；隐藏的界面设置为 `inert`，不会被键盘误触。
- 静音后全部叙事都能通过画面与字幕理解；字幕可关闭。

## 9. 已知限制

- 自动化测试在无头 Chromium（软件渲染）中进行，尚未在真实的 iPhone / iPad Safari 与低端安卓机上实测帧率与触摸手感；性能监测会自动降级，但最终帧率需要真机确认。
- 蓝鲸的歌声是东北太平洋种群（蒙特雷湾）的录音；故事设定在南大洋的夏季，那里的南极蓝鲸唱的是另一种“Z 叫声”（约 28 赫兹缓缓降到 18 赫兹）。录音加速了 6 倍，节奏也随之加快。
- 声音中有几项是“处理过的替代录音”，不是该事件本身的录音：鲸鱼的喷气与吸气（海蚀洞的涌浪加降调的人的呼吸）、拍尾推水、吞水、着地、撕咬（见「声音」）；本环境取不到许可合适的真实鲸鱼喷气录音。海鸥录音来自开源应用 Moodist，其仓库声明素材为 Pixabay Content License 或 CC0，**未能逐个文件核实**，商用前请核实或替换。混音只用离线渲染的客观指标检查过，尚未在手机外放上实际试听（见 `docs/sound/mix-report.md`）。
- 水下与高空、高空与水线中景之间使用“运动匹配 + 转场”（冲出水面的水线与镜头水滴、涌过的浪花水雾），而非真正的三维镜头摇臂。
- 侧视的鲸鱼是绘画，高空俯视的鲸鱼是由侧视画的皮肤与腹面画的轮廓合成的背面画；翻身是对侧视画的近似（远侧的一面用近侧上下翻过来代替），转到一半时腹面的褶沟会有轻微的错位；画中的胸鳍是按轮廓切出来的一层（下面的身体由 `scripts/fin-cutout.py` 补画）；游动时只在画面平面内绕根部小角度转动，下沉途中按三维方向的投影摆放（变短、翻转、变窄都是对同一张侧视画的近似，不是真正立体的胸鳍），滤食（张嘴的画、鼓起的喉囊）与静卧时保持画中的姿态；尾叶的偏转是对画面的整体旋转，翻身途中正对镜头的尾叶由画中的尾叶与它的翻转叠加近似。
- 张嘴到约 90° 是对张嘴那张画（约 30°）的程序化变形：喉囊上的褶沟被扇形拉伸，近看时笔触会被拉长；如果需要更精细的张嘴，可以补一张真正张到 90° 的原画。
- 自由探索中点击骨骼按画中的分区判断类别，肋骨与肩胛骨、胸鳍骨重叠处的判断是近似的。
- 鲸落演替被艺术化压缩为几个阶段，各类生物的出现时间只是示意（字幕中已避免“固定顺序”的说法）。
- 睡鲨、盲鳗与端足类是程序绘制的矢量图形（带斑驳与渐变），与水彩画的鲸鱼风格并不完全一致；伤口画在侧视画的近侧，按画面平面放置。
- 旁白音色是按客观指标（基频、起伏、干净程度、语音识别准确率）从开源模型中选出的，生成过程中没有人试听；个别词语音识别会听成同音字（见 `docs/narration.md`），上线后建议真人试听一遍。
- 骨骼表面的细菌席、食骨蠕虫附着在从骨骼画中找出的朝上表面上；铠甲虾、螺类沿近似的骨骼顶面轮廓移动，偶尔会与骨骼有几厘米的偏差。
- 快速上升（第 8～9 章）是对上千米深度的艺术化压缩。
- 下沉同样经过艺术化压缩：画面中鲸鱼相对海水约 2.3 m/s 缓慢下沉，深度计在深海段则以约 80 m/s 的速度变化。途中只保留少数几次与中层生物的相遇，其余中层生物在下沉时隐去。
- 叙事镜头叠加的轻微“手持”漂移（景别的 0.6%）由氛围时钟驱动，暂停时仍会缓慢呼吸；鲸鱼的位置、姿态与镜头的基本机位只由进度决定。减少动态效果时关闭漂移。
