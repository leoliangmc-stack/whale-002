# 中文旁白（narration）

每条字幕（`src/config/stages.ts` 的 `CAPTIONS`，共 22 条）对应一段女声旁白：

- 音频：`public/assets/narration/NN.mp3`（NN 是 CAPTIONS 的下标，从 00 开始）
- 索引：`public/assets/narration/index.json`，格式 `{ i, file, duration, text }`。`duration` 是音频内容的实际时长；MP3 容器报的时长会多 0.05–0.07 秒（编码器填充）。`text` 是朗读用的规范化文本。
- 生成脚本：`scripts/narration-tts.py`，可重复运行，用法见文件开头的说明。模型文件不进仓库。

规格：单声道 24 kHz，MP3 CBR 64 kbps；首尾各留约 0.1 秒静音；text 与 sub 之间停顿 0.35 秒；每条积分响度 −18 LUFS（ffmpeg ebur128，误差 ±0.1），真峰值 −2.3 至 −2.6 dBTP；22 个文件加索引共 873 KB，总时长 109.5 秒。

## 模型与音色

- **模型**：Kokoro-82M v1.1-zh（hexgrad），用的是 sherpa-onnx 的转换包 `kokoro-multi-lang-v1_1`（GitHub releases → `tts-models`），通过 `pip install sherpa-onnx`（2.0.0）在 CPU 上本地推理，不调用任何付费 API。
- **音色**：`zf_094`（sid 56）。
- **为什么选它**：先用同样的 3 条文本把 55 个中文女声 zf_* 全部合成一遍，再挑 5 个用全部 22 条比较（详见下面的“候选音色”）。zf_094 的基频中位数约 200 Hz（各条在 188–219 Hz 之间），落在 170–220 Hz 的中低音区；起伏适中（5–95% 分位相差约 12 个半音）；谐噪比约 16 dB，声音干净、不气声；高频（>7 kHz）能量比 4 kHz 以下低约 29 dB，没有嘶声或电音；共振峰间距约 1280 Hz，是成年女声的正常范围，没有童声感。两套 ASR 回听时它的听错最少（其他候选反复出现 sh→zh、l→n、in→ing 之类的混淆）。
- 我没法试听，选择只依据上面这些客观指标。建议有人先听一遍 `00.mp3` 和各候选样本，再最终确定。

## 许可

- **Kokoro 权重**：Apache-2.0（包内附 LICENSE，模型卡见 https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh）。可以商用，生成的音频没有额外限制。建议在致谢里写上“旁白：Kokoro-82M v1.1-zh（Apache-2.0）”。
- **训练数据**：Kokoro 作者说明训练只用了许可宽松或无版权的数据（含合成数据）。据我记得的模型卡内容，v1.1-zh 的中文数据由专业数据公司龙猫数据（LongMaoData）提供。这个环境访问不了 Hugging Face，**没能当场核对模型卡原文，上线前请人工确认一次**。
- **其他组件**：sherpa-onnx（Apache-2.0）、jieba 词典（MIT）。包里的 espeak-ng-data（GPL-3.0）只用于英文，本项目全是中文文本，用不到它，也不随网页分发。
- **只用于验证、不分发**：SenseVoice-Small 和 Paraformer-large（FunASR / ModelScope 模型许可）。
- **没有采用的**：MeloTTS 中文（代码和权重 MIT，但中文训练数据来源没有公开）。另外，用标贝（Biaobei）数据训练的 matcha/vits 中文模型只能非商业使用，所以没有作为候选。

## 朗读文本：规范化与改写

显示文字一律不改。下面只是朗读时的处理：

| 显示 | 朗读 |
|---|---|
| 24 米 | 二十四米 |
| 90° | 九十度 |
| “噗——”温暖的呼气…（05） | 不读“噗”，从“温暖的呼气冲出喷气孔……”开始（这一声由真实的鲸鱼喷气音效承担） |
| 一座“鲸落” | 去掉引号 |
| 留下——这叫滤食 | 破折号换成逗号 |
| 聚集…… | 省略号换成句号 |

**前端注音**：sherpa-onnx 的 Kokoro 中文前端只按词典做最长匹配。词典里没有的词会逐字注音，不做三声连读和“一”的变调，多音字也取单字的默认读音（比如“长”单字默认读 zhǎng）。所以脚本另外生成一个附加词典（`USER_LEX`）来覆盖：

- **三声连读**：缓缓、点点、海水、把嘴、哺乳、好几、岛屿、起点、（鲸）骨里、（深）海里、（千）米以，前一字都改读二声。
- **“一”的变调**：一样、一道、一座读 yí；一圈圈、一生、一千读 yì。一头、一个原词典已经正确。
- **轻声**：眼睛读 yǎn jing。
- **多音字**：长尾鳕取“常”的读音，读 cháng wéi xuě（“尾鳕”也按三声连读）。

用 `--phones` 逐条核对了前端实际给出的注音，以下都确认正确：身长 shēn cháng、盲鳗 máng mán、喉腹褶 hóu fù zhě、鲸须 jīng xū、鲸落 jīng luò、落在 luò、端足类 duān zú lèi、食骨蠕虫 shí gǔ rú chóng、磷虾 lín xiā、睡鲨 shuì shā、滤食 lǜ shí、沉积物 chén jī wù、甲壳 jiǎ qiào、细菌 xì jūn、能为 wèi、成为 wéi、着 zhe、地 de、漫长 cháng。“了”在出现了、游过了、闭上了、落在了里读 le，在“到达不了”里读 liǎo。

**两处 ASR 发现的问题**：注音本身是对的，但句首“鲸骨”（16）的 -ng、“磷虾”（01）的 -n 会被后面的辅音带偏，两套 ASR 都听成“金古”“零虾”。办法是在送进 TTS 的文本里加一个空格（Kokoro 的词间停顿符），写成“鲸 骨”“磷 虾”。加了之后识别正确，时长只多约 0.05 秒。

## ASR 回听验证

- **方法**：用 SenseVoice（主）和 Paraformer（交叉验证）识别成品 MP3，与规范化文本比较。比较前把“他/她/它”“的/地/得”统一，因为这些写法听不出区别。
- **两个指标**：字错率（CER）；无调拼音错误率（PER）。PER 不计同音字，衡量的是“读得对不对”。
- **通过标准**：SenseVoice 的 PER 为 0，剩下的字错全是同音字。
- **多次合成取最好**：Kokoro 的声码器带随机噪声，每次合成都略有不同。所以每条最多合成 4 次，留识别最准的一次。
- **结果**：22 条全部通过（SenseVoice 的 PER 全是 0）。CER 不为 0 的条目，错字都是同音字（原文→识别）：喉腹褶→侯腹者、鲸须→精须、留下→留虾、这叫滤食→这教率时、鲸落→经络、盲鳗→忙蛮、睡鲨→睡沙、长尾鳕→长为雪、端足类→端族类、沉积物里→沉积物理、鲸骨→经谷/经古、成为→城为、洋流→杨流。
- **Paraformer 交叉验证**：20 条 PER 为 0。02 条把“蓝鲸”听成“南京”、“喉”听成“投”，12 条把“盲鳗”听成“茫茫”。这几处 SenseVoice 都识别对了，判断主要是 Paraformer 偏向常见词（南京、茫茫）。人工试听时可以留意这几处。

## 时长与语速

- 语速按每条实测自动调整到 3.8–4.5 字/秒（按整段时长算）。只有为了不超出显示时长时，才最多提到 4.9 字/秒。所用的 sherpa-onnx speed 在 0.86 到 1.31 之间。
- **超出显示时长的只有 00**：35 个字，提到 4.85 字/秒后是 7.21 秒，比 6.6 秒多 0.61 秒。如果 00 也按正常的 4.5 字/秒读，大约需要 7.8 秒。
- 01 提到 4.35 字/秒，4.37 秒，刚好在 4.5 秒以内。

## 重新生成

```sh
pip install sherpa-onnx soundfile numpy pypinyin
# 从 https://github.com/k2-fsa/sherpa-onnx/releases 下载并解压：
#   tts-models/kokoro-multi-lang-v1_1.tar.bz2
#   asr-models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17.tar.bz2（可选）
#   asr-models/sherpa-onnx-paraformer-zh-2024-03-09.tar.bz2（可选）
python3 -I scripts/narration-tts.py --model <kokoro 目录> --asr <sense-voice 目录> --paraformer <paraformer 目录>
python3 -I scripts/narration-tts.py --model <kokoro 目录> --phones   # 只看注音
python3 -I scripts/narration-tts.py --model <kokoro 目录> --asr <...> --only 5   # 只重做某几条
```

因为每次合成有随机性，重新生成的音频不会和现在逐字节相同，时长会差几毫秒。
