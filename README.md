# 鲸落：深海之境 · Whale Fall: The Living Abyss

以鲸落生态为主题的 2.5D 沉浸式网页互动体验。用户通过滚动 / 滑动推进一段首尾相接的循环叙事：座头鲸滤食磷虾 → 浮上海面呼吸 → 眼睛缓缓闭上 → 沉入深海 → 落在海床 → 身体逐渐分解 → 鲸骨成为生命岛屿 → 磷虾重新聚集 → 新的鲸鱼从远处游来，并无缝回到开场。完成一圈后解锁“自由探索”，可以拖动、缩放、点击观察鲸骨周围的生态群落。

- 支持 PC、iPad、手机浏览器（Chrome / Safari / Edge，iOS / iPadOS Safari）
- 所有画面均为程序实时绘制，无需任何图片或音频文件；保留了正式资源的替换接口
- 生产包约 213 KB JS（gzip 后约 77 KB）

**在线体验：** https://leoliangmc-stack.github.io/whale-002/

## 1. 运行与构建

需要 Node.js 18+。

```bash
npm install          # 安装依赖（Vite、TypeScript、Vitest）
npm run dev          # 开发服务器（默认 http://localhost:5173，--host 可供局域网手机 / iPad 访问）
npm run build        # 类型检查 + 生产构建，输出到 dist/
npm run preview      # 预览生产构建
npm test             # 单元测试（Vitest，56 项）
```

`dist/` 是纯静态文件，可直接部署到任意静态托管（构建使用相对路径 `base: './'`，放在子目录中也能运行）。

### 部署到 GitHub Pages

每次推送到 `main`，`.github/workflows/deploy-pages.yml` 会自动执行：安装依赖 → 运行单元测试 → 构建 → 把 `dist/` 发布到 `gh-pages` 分支，GitHub Pages 再从该分支上线（仓库 Settings → Pages 的来源为 `gh-pages` 分支、根目录）。测试不通过时不会发布。也可以在 Actions 页面手动运行这个工作流。

### 辅助脚本（需要 Playwright，环境中已有全局安装时会自动使用）

故事默认以约 4.8 分钟一圈的节奏缓缓自动播放，用户的滚动会叠加在自动播放之上；停止滚动 1.6 秒后恢复自动播放。暂停时故事进度停止，但仍可以滚动回看。

滚动距离按镜头分配：开场的五个镜头每个约对应一屏高度的滚动，用户可以在任何一个镜头上停下来慢慢看；其余段落一整圈约 34 屏。

## 3. 技术方案

**TypeScript + Vite + 原生 Canvas 2D**，无运行时依赖。

### 关于没有采用 Phaser 3（与需求文档推荐技术栈的差异）

需求文档推荐 Phaser 3，同时要求“遇到技术选择时优先选择稳定、可维护的实现，不要引入不必要的复杂框架”。评估后选择了原生 Canvas 2D：

1. **画面全部是程序化矢量绘制**（可弯曲的鲸鱼身体、张嘴鼓喉、渐进分解、骨骼坍塌）。Phaser 的 Graphics 对象不支持任意路径的线性 / 径向渐变，而这些正是体积感与水下光照的基础；若改用 CanvasTexture 每帧重绘再上传 GPU，在手机上反而更慢。
2. **叙事由滚动进度驱动，而不是游戏循环**：所有状态是进度的纯函数，Phaser 的场景 / 物理 / Tween 体系基本用不上。
3. 体积更小：整个项目约 213 KB（gzip 后约 77 KB），而 Phaser 3 的完整构建本身就约 1 MB（未压缩），首屏更快。

模块划分仍然沿用了文档中的 12 个模块（见下表），如果未来需要 WebGL 或 Three.js，只需替换渲染层。

### 核心设计

- **统一的进度系统**：完整叙事映射为 `storyProgress ∈ [0,1)`。镜头、鲸鱼、磷虾、光照、粒子、生物数量、骨骼状态全部由同一套关键帧轨道（`core/Track.ts`，单调三次插值，不过冲）从进度求值，任何模块都不单独监听滚动事件。因此正放、倒放、重播得到完全一致的画面。
- **关键镜头保护**：显示进度以受限速度追赶目标进度；关键镜头段（开场五镜头、滤食、喷气、闭眼、着陆、分解、新鲸鱼……）的最高速度更低，快速滚动会“快放”经过，而不会直接跳过。每一段还可以单独指定滚动长度（`Segment.screens`），换算由 `StoryProgressController.advance()` 逐段完成，可以正反向跨圈。
- **无缝循环**：镜头是循环轨道（在 p=1 与 p=0 处 C1 连续）；新鲸鱼与开场鲸鱼共用同一条“鲸鱼谱系”轨道（`u = p − 1`），磷虾群同理，所以位置、大小、朝向、速度、姿态、海水颜色在衔接处天然一致。单元测试逐项校验横屏与竖屏两种构图下的衔接。
- **真正的 2.5D**：带镜头平移（lens shift）的透视相机，所有对象都有深度 z，背景山脊、岩石、海床、生物、颗粒按真实透视产生视差；水体雾化按深度与距离计算。
- **鲸鱼**：脊线 + 背腹剖面的可变形模型。尾叶上下摆动（须鲸的推进方式），滤食时下颌绕颌关节张开、喉腹褶鼓起、鲸须板可见；分解时在离屏图层中逐渐挖出边缘柔和的空洞并收缩轮廓，露出同一条脊线上的骨骼。
- **下沉动作**（`systems/DescentMotion.ts`）：从最后几次摆尾到落上海床是一段确定性的物理模拟——推力、浮力变化、二次阻力、头重力矩、水流与海床接触——在“故事时间”（自动播放的秒数）上积分一次并制成查找表，查表只依赖进度，因此暂停、倒放、跳转都得到同一姿态。尾柄、尾叶、左右胸鳍与头部是由二阶阻尼跟随驱动的被动层，惯性与滞后各不相同；镜头跟随点也带有同样的质量感（匀速时不落后，起动、减速时才滞后）。
- **水体参照系**：1800 米的下沉被艺术化压缩，但鲸鱼相对周围海水的可见下沉只有约 2 m/s。海洋雪、途中相遇的少数生物与海床都锚定在水体参照系中，被压缩的深度由镜头与鲸鱼一起整体带走；深度计、水色与光照仍按真实深度变化。鲸鱼经过时，附近的颗粒会被轻轻推开、身后的颗粒被稍稍带走。
- **鲸骨**：头骨、两侧下颌骨、约 52 节椎骨、14 对肋骨、人字骨、肩胛骨、胸鳍指骨、退化骨盆；坍塌、沉积物覆盖、细菌席与食骨蠕虫随进度生长。几何按坍塌程度缓存为少数几条合并路径，每帧只需几次填充。

## 4. 目录结构与关键模块

```

  systems/                   StoryTimeline、ParallaxManager、LightingManager、ParticleManager、Seabed、
                             OceanSurface、CreatureManager、EcologyManager、AudioManager、
```

## 5. 叙事阶段一览

| 进度 | 章节 | 主要内容 |
|---|---|---|
| 0.00–0.075 | 开场：鲸鱼的庞大与安宁（约 25 秒，五个连续镜头，见下） | 超远景建立尺度 → 侧面全景跟拍 → 低角度仰拍 → 眼睛与皮肤细节 → 磷虾群揭示 |
| 0.075–0.12 | 广阔海洋与磷虾群 | 鲸鱼转向磷虾群 → 推镜头滤食：张嘴、喉腹褶鼓起、磷虾被吸入、闭嘴滤水 |
| 0.12–0.22 | 返回海面与呼吸 | 仰望明亮海面上浮 → 交叉溶解为高空俯视（水波扩散、第一次呼气）→ 镜头下降到水线的中景：背部、喷气孔、水雾柱与淡淡彩虹 |
| 0.22–0.30 | 眼睛缓缓闭上 | 推近到眼睛特写，眼睑分两次缓慢合上，尾叶仍在微弱地摆动，短暂停留 |
| 0.30–0.48 | 缓缓下沉（约 56 秒，五个连续镜头，见下） | 最后几次摆尾渐弱 → 向前滑行、保持水平 → 头部先沉、身体缓缓倾斜 → 稳定下沉 → 深海中安静地漂沉；光线减弱、红色先消失，途中与栉水母、灯笼鱼、冠水母擦身而过；右侧深度计 |
| 0.48–0.55 | 抵达海底 | 海床从幽暗中慢慢浮现，水垫让下沉逐渐放缓，前腹先触底、尾部最后落下，柔和的沉积物云缓慢扩散沉降 |
| 0.55–0.70 | 身体逐渐分解 | 时间提示（数天 → 约 2 年），盲鳗、睡鲨、长尾鳕、端足类、深海蟹陆续到来，软组织渐进变薄、出现空洞、露出骨骼 |
| 0.70–0.80 | 鲸骨成为栖息地 | 镜头沿骨骼推近：细菌席、食骨蠕虫、多毛类、贻贝 / 蛤、螺、铠甲虾、海猪、蛇尾、稀疏的生物发光 |
| 0.80–0.87 | 磷虾重新出现 | 远处零星橙红色身影 → 聚集成群 → 向上漂移离开鲸骨（字幕说明营养循环，不暗示鲸骨生成磷虾） |
| 0.87–0.96 | 新鲸鱼从远处出现 | 随磷虾上升，水色变亮；极远景中出现柔焦的巨大轮廓，逐渐清晰 |
| 0.96–1.00 | 生命的循环 | 构图、速度、光照逐项收敛到开场画面，无闪黑、无跳帧地回到 0 |

### 开场五镜头（阶段 1 前半段）

开场先建立鲸鱼的体型、力量与安宁，再进入捕食。五个镜头是同一条连续的机位运动（推、跟、升降、对焦转移），没有跳切；配置见 `config/stages.ts` 的 `OPENING_SHOTS` 与 `systems/StoryTimeline.ts` 的 `CAM_ROWS`。

| 进度 | 镜头 | 自动播放 | 画面 |
|---|---|---|---|
| 0.000–0.014 | 超远景建立尺度 | 5 秒 | 辽阔的蓝色海水、柔和的光束与漂浮颗粒，鲸鱼从远处的雾蓝中缓缓游来，在画面中只占很小的比例 |
| 0.014–0.030 | 侧面全景跟拍 | 5 秒 | 机位与鲸鱼平行移动，完整呈现头部、身体、胸鳍与尾鳍；尾叶慢速摆动，身体随之起伏 |
| 0.030–0.047 | 低角度仰拍 | 5 秒 | 机位缓缓沉到鲸鱼下方，庞大的身体从画面上方经过；明亮的海面天光从上方透下，身体逆光变暗，背部边缘被勾出柔和光边 |
| 0.047–0.061 | 眼睛与皮肤细节 | 5 秒 | 镜头缓慢升起并推近眼睛：近景加入毛孔、斑点与浅褶痕的皮肤细节和柔和顶光（与之后“眼睛缓缓闭上”形成呼应）；第一只橙红色的磷虾从眼前漂过 |
| 0.061–0.075 | 磷虾群揭示 | 5.5 秒 | 先是零星几只，再缓缓拉远，前方的磷虾越聚越多；鲸鱼放平身体、慢慢转向虾群（竖屏下构图沿对角线转向） |

动作原则：鲸鱼的速度、转向角速度和镜头的推拉速度都有上限（单元测试校验：游速 < 5.5 m/s、转向 < 0.1 rad/s、景别变化 < 40%/s、开场全程不张嘴）；尾叶摆动频率降为约 0.17–0.25 Hz，并让身体随每次推进有轻微的上下起伏，体现大型动物的重量与惯性。开场只有两声远处传来的低吟，不叠加其他音效。

### 下沉：从停止游动到落上海床（阶段 3 末 ~ 阶段 5）

鲸鱼不是被整体向下移动，而是先停止主动游动，再逐渐失去浮力与平衡。动作来自 `systems/DescentMotion.ts` 的确定性模拟，镜头配置见 `systems/StoryTimeline.ts` 的 `CAM_ROWS`，各段时长见 `config/stages.ts` 的 `SEGMENTS`。

| 进度 | 镜头 | 自动播放 | 动作 |
|---|---|---|---|
| 0.285–0.297 | 闭眼特写 | 4 秒 | 眼睛已经合上；尾叶仍在微弱地摆动（从这里起由叙事进度驱动） |
| 0.297–0.320 | 侧面中远景 | 12 秒 | 镜头从眼睛缓缓拉开：最后一两次摆尾幅度渐小、频率渐慢；摆动停止后身体靠惯性继续向前滑行，从画面左侧滑向中央，近乎水平，胸鳍自然展开 |
| 0.320–0.336 | 略低于鲸鱼的仰视 | 8 秒 | 镜头沉到身体下方，庞大的身体逆着海面的光从上方缓缓滑过；仍然水平，几乎没有下沉 |
| 0.336–0.360 | 斜侧面跟随 | 8 秒 | 头部先沉（前 7 秒吻端下沉约 1 米，尾部几乎不动），随后整个身体跟随；下沉速度从 0 平滑增加，尾柄与尾叶被自下而上的水流托起，胸鳍随之抬起并延迟摆动 |
| 0.360–0.410 | 缓慢拉远 | 12 秒 | 稳定下沉（约 2 m/s，保持 8°–10° 的低头），景别从 21 米拉到 40 米以上，四周越来越暗、越来越空 |
| 0.410–0.497 | 远景持续跟随 | 22 秒 | 深蓝中的一个安静身影，只有极轻的俯仰修正与鳍的被动摆动；海床在最后约 25 米从幽暗中浮现，水垫让下沉逐渐放缓 |
| 0.497–0.512 | 着陆 | 4 秒 | 以约 0.25 m/s 接触海床，前腹先触底、身体顺势放平，尾部最后落下；沉积物云扬起 |

动作原则（单元测试 `tests/descent.test.ts` 逐项校验）：摆尾幅度单调减小、频率降低；摆尾停止后至少 4 秒才开始明显下沉；头部先沉 1 米时尾部的高度变化小于 0.3 米；下沉加速度不超过 0.3 m/s²，速度在约 2 m/s 处趋于平稳、不会无休止地加速；俯仰始终小于 0.22 rad、角速度小于 0.035 rad/s，没有持续摇晃；触底时刻、静卧姿态与交接处的位置和速度连续；任意顺序求值结果一致。

## 6. 正式资源的替换接口

- 在 `public/assets/manifest.json` 中登记纹理与音频即可覆盖程序化资源，例如：
  ```json
  {
    "textures": { "krill": "sprites/krill.png", "caustic": "fx/caustic.png", "mist": "fx/mist.png" },
    "audio": { "whaleCall": "audio/humpback.mp3", "spout": "audio/spout.mp3" }
  }
  ```
  纹理键见 `core/textures.ts` 的 `TextureSet`，音频键见 `AudioManager.overrides`。
- 鲸鱼、鲸骨、生物都通过 `prepare()` / `draw(rc)` 接口绘制，可以整体替换为骨骼动画或分层精灵实现，而不影响叙事时间线、镜头与生态系统。

## 7. 性能与无障碍

- 三档画质（磷虾数量、颗粒、光束、焦散、沉积物、椎骨数量、像素比上限）；手机默认中档。`PerformanceMonitor` 在持续掉帧时自动降级，长时间流畅时尝试恢复。
- 粒子与磷虾使用固定数组，运行中不创建 / 销毁对象；分解与远景柔焦只重绘鲸鱼所在的包围盒区域。
- 页面进入后台时停止渲染并挂起音频。
- 减少动态效果：关闭镜头漂移，降低生物、磷虾与颗粒的运动幅度（默认跟随系统设置，可在设置中切换）。
- 无高频闪烁：生物发光与阳光碎金都是缓慢的亮度变化；快速上升时海洋雪自动降低亮度。
- 所有关键按钮同时有图标与文字标签、`aria-label`、键盘焦点样式，触控区域不小于 44px；字幕与章节有 `aria-live`；隐藏的界面设置为 `inert`，不会被键盘误触。
- 静音后全部叙事都能通过画面与字幕理解；字幕可关闭。

## 9. 已知限制

- 自动化测试在无头 Chromium（软件渲染）中进行，尚未在真实的 iPhone / iPad Safari 与低端安卓机上实测帧率与触摸手感；性能监测会自动降级，但最终帧率需要真机确认。
- 声音为实时合成的占位声音，质感有限，建议替换为正式录音或音效。
- 高空俯视与水线中景之间、水下与高空之间使用“运动匹配 + 交叉溶解”过渡，而非真正的三维镜头摇臂。
- 鲸鱼在侧视、俯视两套模型间切换；在侧视中胸鳍与尾叶的空间旋转是近似表现。
- 鲸落演替被艺术化压缩为几个阶段，各类生物的出现时间只是示意（字幕中已避免“固定顺序”的说法）。
- 骨骼表面的细菌席、食骨蠕虫附着点是程序生成的近似分布；铠甲虾、螺类沿近似的骨骼顶面轮廓移动，偶尔会与骨骼有几厘米的偏差。
- 快速上升（第 8～9 章）是对上千米深度的艺术化压缩。
- 下沉同样经过艺术化压缩：画面中鲸鱼相对海水约 2 m/s 缓慢下沉，深度计在深海段则以约 80 m/s 的速度变化。途中只保留少数几次与中层生物的相遇，其余中层生物在下沉时隐去。
- 叙事镜头叠加的轻微“手持”漂移（景别的 0.6%）由氛围时钟驱动，暂停时仍会缓慢呼吸；鲸鱼的位置、姿态与镜头的基本机位只由进度决定。减少动态效果时关闭漂移。

## 10. 后续开发清单

8. PWA 离线缓存。
