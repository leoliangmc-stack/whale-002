# 鲸落：深海之境 · 离线混音检查报告

> 音效剪辑师，2026-10-24。没法用耳朵听，这里用客观指标检查第二阶段的混音。**真机（手机外放 + 耳机）试听仍然需要做**，见第 10 节。

## 0. 方法

- `npx vite-node scripts/sound-mix.ts -- --out <目录>`（旁白开）与 `--no-vo`（旁白关）：用浏览器里**同一个**声音导演（`src/systems/audio/director.ts`）与剪辑表（`plan.ts`），按自动播放的节奏把 p = 0 到下一圈 p ≈ 0.04 混成 48 kHz 立体声 WAV（349.5 秒，含循环接缝）。画面数据（相机深度、拍尾相位、下沉速度、生态、睡鲨的咬住与扭身相位）由 `StoryTimeline`、`Whale`、`Feast` 在 node 里按 `NarrativeScene` 的顺序计算（1440×900 横屏构图）。
- 执行层模拟 WebAudio：`setTargetAtTime` 的指数逼近、二阶低通、`StereoPanner` 的等功率声像（单声道素材居中时每声道 −3 dB）、循环床的单声道 −3 dB 补偿、主增益 = 界面音量 100%、安全限幅器（−2 dBFS、20:1、3 ms / 250 ms）。
- 旁白：`public/assets/narration/` 中的真实录音（22 条，narration-tts.py 归一化到 −18 LUFS），按 `Narration` 的规则（进入新字幕时开始、上一条没读完就排队、最多等 3.5 s）模拟；`speaking` / `nextStartIn` 交给导演。
- `python3 -I scripts/sound-report.py <目录>` 测量：BS.1770 积分 / 短时 / 瞬时响度、4 倍过采样的真峰值、削波、旁白压低（同一时刻两次渲染的 BED 母线电平差）、鲸鸣与人声的重叠、接缝前后的电平台阶、300 Hz 高通后的电平（模拟手机扬声器）、循环素材首尾相接处的跳变。
- 另外在无头 Chromium（`vite preview`，`--autoplay-policy=no-user-gesture-required`）里实际运行：开场、跳到出水、跳到着地与撕咬、暂停、静音、进入自由探索——AudioContext 正常运行、分批加载与释放正确、cue 按时触发、控制台没有错误。
- 单元测试 `tests/audio.test.ts`（16 项）：接缝两侧连续、视角（高空没有水下声）、深度曲线、下沉水流、触发顺序、接缝不丢不重复、倒放不触发、快速滚动只留主角且间隔 ≥ 2 s、跳转淡出、鲸鸣等待与 −8 dB、旁白压低的起落时间、manifest 与体积、源码里没有振荡器 / 随机数 / setTimeout / 卷积。

## 10. 已知问题与需要真机确认的事

1. **没有人试听过**。所有判断来自响度、频谱与时间对齐的测量。请在手机外放（音量 50%）与耳机上各听一整圈，按 cue sheet 第 5 节的清单逐条打勾，重点：喷气与吸气是否“像巨大的动物在呼气”（处理过的替代录音）、海鸥是否零星而不像港口、着地是否“柔软而极重”而不是爆炸、撕咬是否克制、拍尾是否像推水而不像鼓。
2. **手机上的低频**：着地（F15，300 Hz 以上 27%）、拍尾（F01，28–39%）、甩头（F18a/b，约 10%）、沉积物（F16，6%）、水流 A08（16%）在手机外放上会明显变轻。已经在 200–900 Hz 加了同一段录音的提升；如果真机上听不见，优先继续提升 200–600 Hz，而不是整体加大音量。
3. **旁白关时整圈 −24.6 LUFS**，接近 −23 ± 2 的下限。如果真机上整体偏轻，可以把各床同时抬 1–2 dB（`plan.ts` 的深度曲线），峰值还有 1.3 dB 的余量。
4. **替代录音**：喷气、吸气、拍尾推水、吞水、着地、撕咬都是用别的真实录音处理出来的；海鸥的许可未能逐个文件核实。需要所有者在外网补：真实的鲸鱼喷气与吸气、单只海鸥的长鸣（CC0 / CC BY / CC BY-SA，不要 NC）、南极蓝鲸 Z 叫声。
5. 竖屏构图（`compAngle`）下相机深度与横屏略有不同，离线渲染用的是横屏；声音的电平只由 p 与相机深度决定，不再受宽高比影响。
6. iPhone 的静音开关：已在支持的浏览器上设置 `navigator.audioSession.type = 'playback'`，需要真机确认。
7. 设置面板里“声音来源与许可见 README”一行在 `UI.ts`，不归声音这边改，请主导开发者添加。
