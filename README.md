# 鲸落：深海之境 · Whale Fall: The Living Abyss

以鲸落生态为主题的 2.5D 沉浸式网页互动体验。用户通过滚动 / 滑动推进一段首尾相接的循环叙事：一头 24 米长的蓝鲸滤食磷虾 → 浮上海面呼吸 → 眼睛缓缓闭上 → 沉入深海 → 落在海床 → 身体逐渐分解 → 鲸骨成为生命岛屿 → 磷虾重新聚集 → 新的鲸鱼从远处游来，并无缝回到开场。完成一圈后解锁“自由探索”，可以拖动、缩放、点击观察鲸骨周围的生态群落。

- 支持 PC、iPad、手机浏览器（Chrome / Safari / Edge，iOS / iPadOS Safari）
- 蓝鲸与鲸骨是 whale-kit 中的水彩画（约 0.8 MB WebP），沿脊线切成条带实时弯曲、张嘴、下沉与分解；其余画面与声音均为程序实时生成，保留了正式资源的替换接口
- 生产包约 227 KB JS（gzip 后约 84 KB），另加 `assets/whale/` 中的绘画

**在线体验：** https://leoliangmc-stack.github.io/whale-002/

## 1. 运行与构建

需要 Node.js 18+。

```bash
npm install          # 安装依赖（Vite、TypeScript、Vitest）
npm run dev          # 开发服务器（默认 http://localhost:5173，--host 可供局域网手机 / iPad 访问）
npm run build        # 类型检查 + 生产构建，输出到 dist/
npm run preview      # 预览生产构建
npm test             # 单元测试（Vitest，86 项）
```

`dist/` 是纯静态文件，可直接部署到任意静态托管（构建使用相对路径 `base: './'`，放在子目录中也能运行）。

### 部署到 GitHub Pages

每次推送到 `main`，`.github/workflows/deploy-pages.yml` 会自动执行：安装依赖 → 运行单元测试 → 构建 → 把 `dist/` 发布到 `gh-pages` 分支，GitHub Pages 再从该分支上线（仓库 Settings → Pages 的来源为 `gh-pages` 分支、根目录）。测试不通过时不会发布。也可以在 Actions 页面手动运行这个工作流。

滚动距离按镜头分配：开场的五个镜头每个约对应一屏高度的滚动，用户可以在任何一个镜头上停下来慢慢看；其余段落一整圈约 34 屏。

## 3. 技术方案

**TypeScript + Vite + 原生 Canvas 2D**，无运行时依赖。

### 关于没有采用 Phaser 3（与需求文档推荐技术栈的差异）

需求文档推荐 Phaser 3，同时要求“遇到技术选择时优先选择稳定、可维护的实现，不要引入不必要的复杂框架”。评估后选择了原生 Canvas 2D：

1. **画面以程序化绘制为主**（可弯曲的鲸鱼身体、张嘴鼓喉、渐进分解、骨骼坍塌都是对绘画或矢量路径的实时变形）。Phaser 的 Graphics 对象不支持任意路径的线性 / 径向渐变，而这些正是体积感与水下光照的基础；若改用 CanvasTexture 每帧重绘再上传 GPU，在手机上反而更慢。
2. **叙事由滚动进度驱动，而不是游戏循环**：所有状态是进度的纯函数，Phaser 的场景 / 物理 / Tween 体系基本用不上。
3. 体积更小：整个项目的代码约 227 KB（gzip 后约 84 KB），而 Phaser 3 的完整构建本身就约 1 MB（未压缩），首屏更快。

模块划分仍然沿用了文档中的 12 个模块（见下表），如果未来需要 WebGL 或 Three.js，只需替换渲染层。

### 核心设计

- **统一的进度系统**：完整叙事映射为 `storyProgress ∈ [0,1)`。镜头、鲸鱼、磷虾、光照、粒子、生物数量、骨骼状态全部由同一套关键帧轨道（`core/Track.ts`，单调三次插值，不过冲）从进度求值，任何模块都不单独监听滚动事件。因此正放、倒放、重播得到完全一致的画面。
- **关键镜头保护**：显示进度以受限速度追赶目标进度；关键镜头段（开场五镜头、滤食、喷气、闭眼、着陆、分解、新鲸鱼……）的最高速度更低，快速滚动会“快放”经过，而不会直接跳过。每一段还可以单独指定滚动长度（`Segment.screens`），换算由 `StoryProgressController.advance()` 逐段完成，可以正反向跨圈。
- **无缝循环**：镜头是循环轨道（在 p=1 与 p=0 处 C1 连续）；新鲸鱼与开场鲸鱼共用同一条“鲸鱼谱系”轨道（`u = p − 1`），磷虾群同理，所以位置、大小、朝向、速度、姿态、海水颜色在衔接处天然一致。单元测试逐项校验横屏与竖屏两种构图下的衔接。
- **真正的 2.5D**：带镜头平移（lens shift）的透视相机，所有对象都有深度 z，背景山脊、岩石、海床、生物、颗粒按真实透视产生视差；水体雾化按深度与距离计算。
- **鲸鱼**：一头 24 米长的蓝鲸。几何是脊线 + 背腹剖面的可变形模型（剖面从绘画的轮廓量出，`entities/WhaleBody.ts`），画面是 whale-kit 的水彩画（`entities/WhaleArt.ts`）：沿体轴切成约 0.3 米宽的条带，每条按脊线的位置与方向摆放，所以身体能随尾叶上下摆动、下沉时弯曲、静卧时贴合海床；体轴上下两半可以分别缩放（喉囊鼓起、分解时软组织收缩）。滤食时张嘴的画（约 30°）按当前的张角连续变形：颌关节以下的扇形（下颌与喉囊）与以上的扇形（吻部）分别按分块仿射变形——张得更大时下颌继续下转到约 90°（须鲸冲刺滤食时上下颌张角接近 90°），喉囊沿半径方向鼓起；张得更小时下颌往上合、画中微微抬起的吻部绕颌关节放下来，合拢时与游动的画重合，所以两张画只在嘴几乎闭上的一瞬间交接，张嘴与闭嘴都看不出换画；上下颌之间的缝隙保持透明。下沉时身体可以绕体轴翻过来（`WhaleBody.rolledHeight`）：把横截面看成近似的椭圆，转动途中每条带沿横截面分块、按转动后的高度重新排布，越过腹中线后用画上下翻过来代替远侧的一面（左右对称），并按转动后平滑的轮廓裁剪；肚子朝上时整幅画沿体轴翻转。眼睛特写与闭眼使用两张高分辨率的眼睛画（预处理中把夕阳暖光改为水下冷光、与身体画对色），眼睑从睁眼的画扫到闭眼的画。画面在离屏图层中按深度着色（与程序绘制的物体同一个光照模型），远处的鲸鱼使用预先缩小的版本，分解时挖出边缘柔和的空洞，露出同一条脊线上的骨骼。
- **游动动作**（`systems/SwimMotion.ts`）：开场到滤食同样是在故事时间上积分一次的确定性动作表：几次缓慢有力的拍尾（约 0.14–0.22 Hz，上拍比回程快，每一次的幅度与频率略有不同）与短暂的滑行交替；推力（幅度² × 频率²）减去阻力驱动速度的缓慢起伏，拍尾时略微加速、滑行时略微减速；路径的关键帧按秒插值，镜头段之间没有速度突变；俯仰跟随路径方向并略微领先（身体先转、路径随后），先保持深度、再以约 12° 平缓下潜、在磷虾群前放平；冲刺滤食前加快拍尾，张嘴后停止拍尾、靠惯性滑行减速。胸鳍、尾柄与头部是被动层：滑行时胸鳍微微张开，转向、上浮时调整角度，用力拍尾时贴近身体。拍尾相位由故事时间决定（两头鲸鱼共用，循环衔接处一致），用户停下时叠加一个缓慢的悬停轻摆。身体经过时推开附近的海洋雪，尾叶每次拍动都把身边的颗粒推开一点并带起小小的旋涡。叙事镜头的关键帧也按故事时间插值，推拉与平移的速度在段边界处连续，镜头跟随点在加速、减速与调整深度时稍稍滞后。
- **下沉动作**（`systems/DescentMotion.ts`）：从最后几次摆尾到落上海床是一段确定性的物理模拟——推力、浮力变化、二次阻力、头重力矩、水流与海床接触——在“故事时间”（自动播放的秒数）上积分一次并制成查找表，查表只依赖进度，因此暂停、倒放、跳转都得到同一姿态。尾柄、尾叶与头部是由二阶阻尼跟随驱动的被动层，惯性与滞后各不相同；失去肌张力之后，头部先沉，身体一边下沉一边在约 18 秒里慢慢翻过来、变成肚子朝上（参考画面；深海中再慢慢翻回来，腹部先触底），同时转成约 43° 的低头姿态，从浮力最大的胸腹部“挂”成一道弓形：前半身几乎笔直地斜向下方，背部在体长约七成处拱起，尾柄顺着长弧垂下，尾端斜向下方约 34°（转角场从参考画面中量出，沿脊线按弧长积分，体长不变，`WhaleBody.archAngle`）；下沉时自下而上的水流把尾叶托向尾柄的延长线，画中的胸鳍随水流自然张开、轻轻摆动；低垂的头部带着身体向前滑一点，斜斜地、缓慢安静地沉向深海。俯仰由“拉向目标角度的力矩 + 阻尼”积分得到，带着惯性与滞后，不是直接设定的角度。镜头跟随点也带有同样的质量感（匀速时不落后，起动、减速时才滞后）。
- **水体参照系**：1800 米的下沉被艺术化压缩，但鲸鱼相对周围海水的可见下沉只有约 2.3 m/s（同时向前滑行约 0.75 m/s）。海洋雪、途中相遇的少数生物与海床都锚定在水体参照系中，被压缩的深度由镜头与鲸鱼一起整体带走；深度计、水色与光照仍按真实深度变化。鲸鱼经过时，附近的颗粒会被轻轻推开、身后的颗粒被稍稍带走。
- **鲸骨**：whale-kit 中与身体画同一取景的骨骼画，按同一条脊线切成更细的条带，分解时从空洞里露出的骨头与身体严格对齐。坍塌时整副骨架朝海床压低（胸腔里的肋骨摊开、脊柱落下，头骨只略微下沉），条带之间用剪切保持脊柱连续；沉积物把骨头染成灰褐色。细菌席与食骨蠕虫长在骨头朝上的表面上，这些位置是加载时从骨骼画的透明度中找出来的；自由探索中的点击会换算回画中的像素，按分区判断是头骨、下颌骨、椎骨、肋骨、肩胛骨、胸鳍骨还是退化的骨盆。

## 5. 叙事阶段一览

### 开场五镜头（阶段 1 前半段）

开场先建立鲸鱼的体型、力量与安宁，再进入捕食。五个镜头是同一条连续的机位运动（推、跟、升降、对焦转移），没有跳切；配置见 `config/stages.ts` 的 `OPENING_SHOTS` 与 `systems/StoryTimeline.ts` 的 `CAM_ROWS`。

| 进度 | 镜头 | 自动播放 | 画面 |
|---|---|---|---|
| 0.000–0.014 | 超远景建立尺度 | 5 秒 | 辽阔的蓝色海水、柔和的光束与漂浮颗粒，鲸鱼从远处的雾蓝中缓缓游来，在画面中只占很小的比例 |
| 0.014–0.030 | 侧面全景跟拍 | 5 秒 | 机位与鲸鱼平行移动，完整呈现头部、身体、胸鳍与尾鳍；尾叶慢速摆动，身体随之起伏 |
| 0.030–0.047 | 低角度仰拍 | 5 秒 | 机位缓缓沉到鲸鱼下方，庞大的身体从画面上方经过；明亮的海面天光从上方透下，身体逆光变暗，背部边缘被勾出柔和光边 |
| 0.047–0.061 | 侧面中景 | 5 秒 | 镜头升回与鲸鱼相近的高度，沿身体向头部缓缓平移：头部、胸鳍与前半身在画面中，不推近到眼睛（眼睛的特写留给之后“眼睛缓缓闭上”）；第一只橙红色的磷虾从头前漂过 |
| 0.061–0.075 | 磷虾群揭示 | 5.5 秒 | 先是零星几只，再缓缓拉远，前方的磷虾越聚越多，聚成成千上万只小虾组成的密集虾团；鲸鱼放平身体、慢慢转向虾群（竖屏下构图沿对角线转向） |

动作原则：鲸鱼的速度、转向角速度和镜头的推拉速度都有上限（单元测试校验：游速 < 9.4 m/s（约 0.4 倍体长每秒）、转向 < 0.1 rad/s、景别变化 < 40%/s、开场全程不张嘴）；尾叶摆动频率约 0.14–0.22 Hz（蓝鲸是拍尾最慢的须鲸），身体随每次推进有轻微的上下起伏，体现大型动物的重量与惯性。动作有节奏：侧面跟拍里是一次完整有力的拍尾，仰拍时庞大的身体停止拍尾、胸鳍微张，静静地从上方滑过，侧面中景里恢复拍尾，看见磷虾群时放慢、放平身体，随后加快拍尾冲向虾群（`tests/swim.test.ts` 逐项校验：拍尾与滑行交替、频率不恒定、速度在时间上连续且滑行时减速、俯仰与路径方向一致、胸鳍角度变化且张嘴时回到原位、镜头滞后有界、交还关键帧处连续）。开场只有两声远处传来的低吟，不叠加其他音效。

### 下沉：从停止游动到落上海床（阶段 3 末 ~ 阶段 5）

鲸鱼不是被整体向下移动，而是先停止主动游动，再逐渐失去浮力与平衡。动作来自 `systems/DescentMotion.ts` 的确定性模拟，镜头配置见 `systems/StoryTimeline.ts` 的 `CAM_ROWS`，各段时长见 `config/stages.ts` 的 `SEGMENTS`。

| 进度 | 镜头 | 自动播放 | 动作 |
|---|---|---|---|
| 0.285–0.297 | 闭眼特写 | 4 秒 | 眼睛已经合上；尾叶仍在微弱地摆动（从这里起由叙事进度驱动） |
| 0.297–0.320 | 侧面中远景 | 12 秒 | 镜头从眼睛缓缓拉开：最后一两次摆尾幅度渐小、频率渐慢；摆动停止后身体靠惯性继续向前滑行，从画面左侧滑向中央，近乎水平 |
| 0.320–0.336 | 略低于鲸鱼的仰视 | 8 秒 | 镜头沉到身体下方，庞大的身体逆着海面的光从上方缓缓滑过；仍然近乎水平，开始缓缓下沉，身体也随之开始慢慢翻转。从闭眼之后起，海水与阳光换成参考画面的样子：灰蓝、通透的海水，画面上缘一道明亮起伏的海面，密密的光柱从海面一直照到画面下缘，身体被上方的阳光照得明亮 |
| 0.336–0.360 | 斜侧面跟随（略微仰视） | 8 秒 | 头部先沉（前几秒吻端下沉约 2 米，尾部几乎不动），随后整个身体跟随；失去控制的身体一边下沉一边慢慢翻过来（从上一个镜头开始，约 18 秒，转到一半时腹部朝向镜头，此时下沉已超过 1 m/s；不是翻好之后才下沉），变成肚子朝上，同时慢慢转成低头的姿态、弯成头尾下垂的弓形，翻过来的胸鳍慢慢垂向后下方；下沉速度从 0 平滑增加；镜头略低于鲸鱼，上方透下密集的光柱，鲸鱼在画面中偏上，下方留出它将要沉入的海水——与参考画面的构图和光线一致 |
| 0.360–0.410 | 缓慢拉远 | 12 秒 | 稳定、安静地斜向下沉（相对海水约 2.3 m/s 下沉、约 1 m/s 前滑），保持参考画面中的姿态：肚子朝上，前半身约 43°–47° 低头，腰部到尾巴弯成弓形，尾端斜向下方约 34°；景别从 37 米拉到 65 米以上；参考画面的浅海光照一直保持到约 0.37，随后海面的光带、光柱与灰蓝的海水在约 10 秒里渐渐沉入开阔、清澈的深蓝（约 900 米时光柱淡去），背部有柔和的轮廓光 |
| 0.410–0.497 | 远景持续跟随 | 22 秒 | 深蓝中的一个安静身影（上方仍有一点散射的天光，画面不是一片死黑），只有极轻的俯仰修正、尾叶与胸鳍的被动摆动；深海中慢慢翻回来（约 9 秒），最后约十几秒，水垫让下沉逐渐放缓，身体缓缓放平、弓形舒展开，海床从幽暗中浮现 |
| 0.497–0.518 | 着陆 | 约 5 秒 | 以约 0.25 m/s 接触海床（胸鳍与身体的弧度此前已回到静卧的姿态）：前腹先触底，胸腹部在约 2 秒内再压进软泥约 0.34 米；头部随后放低；尾柄最后落下，尾叶触底时有一次约 6 厘米、很快消失的下压。大团细沉积物沿腹部依次被挤出、向上翻涌到约 5 米高，贴着海床向两侧涌出，鲸鱼身后扬起一层宽阔的尘雾，约 12 秒后沉降完毕 |

动作原则（单元测试 `tests/descent.test.ts` 逐项校验）：摆尾幅度单调减小、频率降低；摆尾停止后至少 4 秒才开始明显下沉；头部先沉 1.7 米时尾部的高度变化小于 0.5 米（按弯曲之后的实际位置），转成低头姿态用时超过 11 秒；下沉加速度不超过 0.51 m/s²，速度在约 2.3 m/s 处趋于平稳、不会无休止地加速，并且向前滑一点（运动方向偏离竖直方向 10°–30°）；俯仰角速度小于 0.09 rad/s，没有持续摇晃；稳定下沉时的姿态与参考画面一致（胸部 38°–47°、头部 42°–52° 低头，尾端斜向下方 26°–44°，背部最高处在体长的六成到八成之间），弯曲保持体长、任意 1 米内方向变化小于 10°；胸鳍张开 0.08–0.3 rad 并轻轻摆动，着陆前身体放平、回到画中的姿态；光束在约 1000 米之前消失；触底时刻、静卧姿态与交接处的位置和速度连续；任意顺序求值结果一致。

### 静卧在海床上（阶段 5 之后）

静卧姿态由 `entities/WhaleBody.ts` 的 `restSpineDY` / `restRoll` 给出，接触关系由 `entities/Whale.ts` 的 `updateContact` / `drawContact` / `drawBerm` 绘制，单元测试 `tests/rest.test.ts` 逐项校验：

- **重量**：最重的胸腹部压入沉积物约 0.34 米；头部在颈部附近以长弧线微微放低，下颌贴近海床；尾柄像一道低矮的拱缓缓垂向海床，下方留出最宽约 0.45 米、向尾叶逐渐变窄的缝隙，尾叶顺势落在海床上。弯曲沿脊线保持每一段的长度（体长不变），任意 1 米内方向变化小于 10°，没有压扁、拉长或折角。身体略向镜头一侧侧倾（头部约 13°、尾柄约 3°；只影响接触与压痕，绘画本身不旋转）。
- **鳍与尾叶**：画中的胸鳍贴着身体，随身体一起落下，鳍尖落在镜头一侧的软泥上，压进去的部分被近侧隆起的软泥边缘挡住。尾叶按画中的形状受海床软约束：斜向后下方的下叶尖端接近海床时就被缓缓托起，可以略微陷进软泥，但不会插进海床。
- **接触关系**：按每一段身体实际离海床的高度绘制分区域的软阴影（压入处最深、尾柄与下颌下方较淡较宽，胸鳍与尾叶在落地处各有一小片），另有一层很宽、很淡的环境遮蔽；压入沉积物的部分被近侧隆起的软泥边缘挡住（按透视投影到侧视平面裁剪），边缘有柔和的亮边、暗坡与零星泥块；身体下缘只在接触处加深，没有一圈均匀的黑边。海床上的印痕按未分解的完整身体计算，分解与骨骼阶段依然保留。
- **镜头与光**：着陆后缓慢推近为斜侧面中远景，镜头略高于海床，构图中心在吻端与尾叶之间，头尾完整留在画面内（横屏、竖屏均如此）；深海中加入来自上方的柔和散射光与很克制的冷色轮廓光。

## 6. 正式资源的替换接口

- 在 `public/assets/manifest.json` 中登记纹理与音频即可覆盖程序化资源，例如：
  ```json
  {
    "textures": { "krill": "sprites/krill.png", "caustic": "fx/caustic.png", "mist": "fx/mist.png" },
    "audio": { "whaleCall": "audio/blue-whale.mp3", "spout": "audio/spout.mp3" }
  }
  ```
  纹理键见 `core/textures.ts` 的 `TextureSet`，音频键见 `AudioManager.overrides`。
- 鲸鱼、鲸骨、生物都通过 `prepare()` / `draw(rc)` 接口绘制，可以整体替换为其他实现，而不影响叙事时间线、镜头与生态系统。

### 蓝鲸绘画资源（`public/assets/whale/`）

来自 whale-kit（同一位作者的另一个 Whale Fall 项目，导出于 2026-10-22/23）：六张画由 libtv（General image Pro）按文字提示生成，没有使用任何现有作品作为输入，并经所有者确认；**商用前请先核对 libtv 的输出条款**。在本项目中做了以下处理（原画不在仓库中）：

- `swim` / `lunge` / `skeleton`：三张同一取景的侧视画裁切到同一画框（2870 × 640），清除背景上零星的半透明杂点，保留透明像素下的颜色（避免缩放时出现浅色描边）；锚点（吻端尖、尾叶缺刻、眼睛）见 `entities/WhaleArt.ts`。原画按 14 米标定，这里按 24 米使用。
- `eye-open` / `eye-closed`：缩到 1024 像素，按 kit 中 `relightDaylight()` 的公式把夕阳暖光改为水下冷色顶光，按身体画在眼睛周围的颜色做逐通道校色，并羽化边缘，只保留可能看到的横条。
- `swim-fin-under`：游动的画中胸鳍下面的身体（约 17 KB），由 `python3 scripts/fin-cutout.py` 按 `WhaleArt.ts` 中的胸鳍轮廓 `FIN_POLY` 生成：轮廓外的皮肤作边界做调和填充，再叠加沿体轴方向复制的喉腹褶细节，腹部下缘逐列插值保持清晰。加载时（`WhaleArt.ts` 的 `cutFin`）把轮廓内的原画切成单独的胸鳍图层，轮廓内的身体换成这张补丁；两层按原位叠放时与原画一致。修改轮廓后需要重新运行脚本。
- `dorsal`：俯视的背面画（约 260 KB），由 `python3 scripts/dorsal-art.py <whale-kit/images/web/whale-below.webp>` 生成：whale-kit 中从正下方看的腹面画只提供轮廓（俯视与仰视的轮廓相同），轮廓内画上背部——俯视中离脊线的相对距离对应侧视画中体轴上方的高度，取游动画中相应位置的皮肤，左右两侧沿体轴错开取画（斑纹不会左右镜像），再加顶光的明暗、胸鳍与尾叶的皮肤、很淡的喷气孔、防溅脊与背鳍。锚点见 `WhaleArt.ts` 的 `DORSAL_ART`。
- 身体与张嘴画的轮廓（`WhaleBody.ts` 的 `UPPER` / `LOWER` / `LUNGE_UP` / `LUNGE_LO`）、胸鳍与尾叶的位置、骨骼画的分区都是从画中量出来的；换成另一套同一取景的画时，需要同步更新这些数据。

## 7. 性能与无障碍

- 三档画质（磷虾数量与虾团的密集小点层数、颗粒、光束、焦散、沉积物、像素比上限）；手机默认中档。`PerformanceMonitor` 在持续掉帧时自动降级，长时间流畅时尝试恢复。
- 海水渐变、天光、层层叠叠的光束与参考画面上缘的海面波光都很柔和，合在同一张 1/4 分辨率的离屏图层上绘制（每排波光是一次按纹理坐标缩放的平铺填充），再一次性放大铺满画面，几乎没有全屏填充的开销。
- 粒子与磷虾使用固定数组，运行中不创建 / 销毁对象；鲸鱼只在所在的包围盒区域内用离屏图层合成，深度着色合并为一次填充，远处的鲸鱼使用预先缩小的绘画。
- 页面进入后台时停止渲染并挂起音频。
- 减少动态效果：关闭镜头漂移，降低生物、磷虾与颗粒的运动幅度（默认跟随系统设置，可在设置中切换）。
- 无高频闪烁：生物发光与阳光碎金都是缓慢的亮度变化；快速上升时海洋雪自动降低亮度。
- 所有关键按钮同时有图标与文字标签、`aria-label`、键盘焦点样式，触控区域不小于 44px；字幕与章节有 `aria-live`；隐藏的界面设置为 `inert`，不会被键盘误触。
- 静音后全部叙事都能通过画面与字幕理解；字幕可关闭。

## 9. 已知限制

- 自动化测试在无头 Chromium（软件渲染）中进行，尚未在真实的 iPhone / iPad Safari 与低端安卓机上实测帧率与触摸手感；性能监测会自动降级，但最终帧率需要真机确认。
- 声音为实时合成的占位声音，质感有限，建议替换为正式录音或音效。蓝鲸的真实叫声在 10~40 赫兹、大多低于人耳听阈，合成的叫声整体移高了约两个八度。
- 水下与高空、高空与水线中景之间使用“运动匹配 + 转场”（冲出水面的水线与镜头水滴、涌过的浪花水雾），而非真正的三维镜头摇臂。
- 侧视的鲸鱼是绘画，高空俯视的鲸鱼是由侧视画的皮肤与腹面画的轮廓合成的背面画；翻身是对侧视画的近似（远侧的一面用近侧上下翻过来代替），转到一半时腹面的褶沟会有轻微的错位；画中的胸鳍是按轮廓切出来的一层（下面的身体由 `scripts/fin-cutout.py` 补画），只能在画面平面内绕根部小角度转动，滤食（张嘴的画、鼓起的喉囊）、下沉与静卧时保持画中的姿态；尾叶的偏转是对画面的整体旋转。
- 张嘴到约 90° 是对张嘴那张画（约 30°）的程序化变形：喉囊上的褶沟被扇形拉伸，近看时笔触会被拉长；如果需要更精细的张嘴，可以补一张真正张到 90° 的原画。
- 自由探索中点击骨骼按画中的分区判断类别，肋骨与肩胛骨、胸鳍骨重叠处的判断是近似的。
- 鲸落演替被艺术化压缩为几个阶段，各类生物的出现时间只是示意（字幕中已避免“固定顺序”的说法）。
- 骨骼表面的细菌席、食骨蠕虫附着在从骨骼画中找出的朝上表面上；铠甲虾、螺类沿近似的骨骼顶面轮廓移动，偶尔会与骨骼有几厘米的偏差。
- 快速上升（第 8～9 章）是对上千米深度的艺术化压缩。
- 下沉同样经过艺术化压缩：画面中鲸鱼相对海水约 2.3 m/s 缓慢下沉，深度计在深海段则以约 80 m/s 的速度变化。途中只保留少数几次与中层生物的相遇，其余中层生物在下沉时隐去。
- 叙事镜头叠加的轻微“手持”漂移（景别的 0.6%）由氛围时钟驱动，暂停时仍会缓慢呼吸；鲸鱼的位置、姿态与镜头的基本机位只由进度决定。减少动态效果时关闭漂移。

## 10. 后续开发清单

1. 真机测试与调优：iOS Safari 的触摸惯性、低端设备的画质分级阈值。
2. 正式美术资源：张嘴到 90° 的蓝鲸原画、单独绘制（可以立体转动）的胸鳍、正式绘制的俯视背面画与腹面画（翻身时用）、生物精灵图集（通过 AssetRegistry 接入）。
3. 正式声音设计：蓝鲸叫声录音（加速后可听）、分层的海洋环境声、空间化混音。
4. 镜头：可选的 WebGL 后期（景深、体积光），或用 Three.js 实现真正的海面摇臂镜头。
5. 自由探索：更多可观察物种、跟随镜头的平滑转向、按生态时间解锁的新群落、探索记录导出 / 分享。
6. 更多鲸落演替阶段（如长期的“礁岩阶段”）与不同深度、不同鲸种的鲸落对比。
7. 多语言（英文字幕与科普）。
8. PWA 离线缓存。
