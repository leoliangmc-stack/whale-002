## 0. 约定（先读）

- **所有时间点以叙事进度 p 为准**（0 ≤ p < 1）。表中的“参考秒”按工作区当前的 `SEGMENTS`（`secondsAt(p)`，一圈 336.5 秒）换算，只用于审听时对照。
  - 段长如果再改，p 点本身不变，只需重算参考秒；阶段 6、7 内与动画对齐的点以代码里的事件为准（见 1.8），不要抄本表的数字写死。
- **电平写法**：“目标 −27”指该元素单独播放、界面音量 100% 时，在输出端测得的**短时响度 LUFS-S（3 秒窗）**；一次性音效指它的短时响度最大值。所有素材文件统一归一化到 −18 LUFS（循环床按积分响度，一次性素材按短时最大值），所以**运行时增益（dB）= 目标 + 18**，例如目标 −27 → 增益 −9 dB。“关”= 增益 0 并按渐变时间降到 0。
- **相机深度 d** = `camera.cam.cy`（米，正值在水下）。下文的“深度曲线”都以 d 为自变量，与屏幕宽高比无关。
- 层名缩写：BED 环境床、SFX 动作音效、BIO 生物叫声、VO 旁白、UI 界面提示。
- 素材编号：A = 循环床，F = 一次性音效，V = 鲸鸣（详见第 3 节）。

## 1. 总体原则

### 1.1 目标

1. **真实录音为主**：每一个叙事声音都来自真实录音（水听器、实地录音），允许滤波、变调、拼接、包络等后期处理；**不再用振荡器或程序噪声从零合成任何叙事声音**。
2. **少而精**：任何时刻最多 1 个“主角”声音（hero）+ 1–2 层环境；每个声音都要能回答“画面里哪个东西发出它”。
3. **视角可信**：镜头在水下就只听见水下的声音，在空中就只听见空气中的声音，水线镜头两者兼有。
4. **给旁白留空间**：旁白开着时环境自动让位；鲸鸣排在旁白的空档里。
5. **手机外放能听见**：每个关键声音在 300 Hz–4 kHz 之间必须有足够能量（手机扬声器几乎放不出 300 Hz 以下）。
6. **确定性**：连续层的电平与滤波是 p 的纯函数（与画面一致，正放、倒放、跳转得到同一状态）；一次性音效只在正向经过时触发；不使用 `Math.random()` 决定时间或电平（变体选择按序号轮换）。

### 1.2 现有方案为什么“乱七八糟”（这些全部删除）

逐条对照 `src/systems/AudioManager.ts` 与实测数据：

1. **层太多、永不归零**：水下噪声、浪声、风、三个正弦低频（48/72/97 Hz）、下沉水流、合唱、混响 7 条持续层同时运行，最低增益也不为 0（低频 0.03、水下 0.22 起），叠成一团“嘶——嗡——”。
2. **噪声床本身有缺陷**：6 秒的褐噪声缓冲首尾各做 50 ms 淡化后循环，每 6 秒出现一次可闻的凹陷；下沉水流以 2.3 倍速播放同一缓冲，变成每 2.6 秒一次的“呼吸式”起伏；白噪声 5 秒循环，听起来像收音机静电而不是海。
3. **视角错误**：“靠近海面”的权重用 `1 − |相机深度|/30` 计算。实测开场相机深度 12.7 米 → 权重 0.58，闭眼段相机 11–14 米 → 0.55，于是**水下镜头里一直播放空气中的浪声嘶声**。
4. **所有声音共用一个 4.2 秒的噪声混响**：空中的喷气、水下的着地、深海的咔哒、界面提示音都在同一个“大教堂”里，水上水下没有区别，混响尾巴本身也是嘶声。
5. **低频“咚”太多且互相混淆**：拍尾（58→34 Hz 正弦）、心跳（64→38 Hz）、着地（46→24 Hz）、吞水（42→30 Hz）都是下滑正弦，耳机里像鼓点，手机外放完全听不见，只剩伴随的噪声。心跳是陈词滥调，也不是真实声音。
6. **真实的鲸鸣在手机上几乎听不见**：频谱分析 `blue-whale-*.mp3` 有 94–97% 的能量在 150–300 Hz（`ocean-chorus.mp3` 有 87% 在 300 Hz 以下）。手机上真实的部分消失了，剩下的全是合成噪声。
7. **与字幕 / 旁白撞车**：远处鲸鸣 p 0.016 落在第一句字幕里，告别鲸鸣 p 0.257 落在“它的眼睛，慢慢地闭上了”里，着地 p 0.4975 紧跟着陆字幕开头。加上旁白之后会彼此掩盖。
8. **随机的咔哒与碎响**：深海每 4–11 秒随机一次带通噪声咔哒、分解阶段随机碎响（900–3100 Hz、Q=3 的噪声脉冲），听起来像扬声器坏了。
9. **触发逻辑的漏洞**：用相邻两帧的 p 差判断正向，p 从 0.999 回到 0.001 时那一帧被当成倒退（接缝附近的 cue 丢失）；快速滚动在 3–6 倍速下每帧 Δp < 0.02 仍全部触发，音效扎堆；气泡用 `setTimeout` 排程，暂停、倒放后仍继续响。
10. **拍尾音量依赖设备**：拍尾的“近”由 `shot.frameH` 决定，而竖屏会被 `needW/aspect` 放大，同一镜头手机比桌面小声。
11. **加载失败时退回合成**：锯齿波“鲸鸣”等后备声音质感廉价，宁可不响。
12. **没有总限幅、没有响度计划**：喷气 0.5 + 着地 0.5 + 合唱叠加时可能削波。

**删除清单**（剪辑师重写 `AudioManager` 时不再保留）：`brownNoise` / `whiteNoise` / `impulse` 及所有由它们构成的床；三个低频振荡器；`whump`、`engulf`、`filterOut`、`splash`、`spout`（合成部分）、`heart`、`thud`、`rise`、`crackle`、`bubble`、`click`、`whaleCall`；`setTimeout` 排程；共享卷积混响。可保留：`unlock / setMuted / setVolume / suspend / resume / samplesReady` 这些对外接口、`AssetRegistry` 的 manifest 加载机制；`chime()`（界面提示，不属于叙事）可保留或换成 F24。

### 1.3 关于 MBARI 真实蓝鲸录音：**保留，但重新母带处理**

- **保留的理由（物种准确性）**：这是一个蓝鲸的故事，MBARI 的录音是真正的蓝鲸 A-B 叫声（东北太平洋种群），CC BY 4.0、来源与处理流程都在 README 里写清楚了，体积小，而且“加速 6 倍才能听见”本身就是值得讲的科学事实。换成座头鲸的歌（观众更熟悉的“鲸歌”）会让主角“唱别的物种的歌”，在一个科普叙事里不可接受。
- **观众听感的问题不在录音，而在频段**：现有文件几乎全部能量在 150–300 Hz，手机放不出来。处理方法（仍是对真实录音的处理，不是合成）：
  1. 以 6 倍速版本为基础层（保持现有节奏与 README 的说法）；`scripts/whale-audio.py` 的上限频率可从 120 Hz 放宽到约 160 Hz 再导出，多保留几个谐波（检查信噪比，不要引入船噪）。
  2. 叠一层**八度层**：把基础层用保持时长的变调（rubberband / librosa 相位声码器）升高 12 个半音，带通 350–1600 Hz，比基础层低 8 dB 混入。耳机里仍是低沉的原声，手机里能听到同一条旋律线的上方泛音。
  3. 验收：300 Hz 以上能量占比 ≥ 35%（现在 1–5%）；听起来仍是“低沉、缓慢下滑的呻吟”，不是口哨或尖叫；没有明显的相位声码器“水声”伪影。
  4. README 的「声音」一节要如实补一句：“为了让手机扬声器也能听见，叠加了同一段录音升高一个八度（时长不变）的版本”。
- 远处合唱 `ocean-chorus.mp3` 同样保留并做同样的八度层处理（电平更低），截成 30 秒无缝循环。
- 备选 / 补充（同一种群、公共领域）：NOAA SanctSound 精选片段里有蒙特雷湾的蓝鲸 A 叫声、B 叫声（含 8 倍速版本）与华盛顿外海的蓝鲸（6 倍速版本），见 3.1。若需要第 4 个不同的叫声，从那里取，不要重复使用同一文件的同一段超过两次。
- 已知限制保持不变：故事设定在南大洋，南极蓝鲸唱的是 Z 叫声；目前没有许可合适、可访问的录音，README「已知限制」里已有说明。

### 1.5 视角（听点）规则：水下 / 水线 / 空中

听点永远是镜头。三种状态与权重：

| 状态 | 进度 | 权重 | 能听到 | 绝不能听到 |
|---|---|---|---|---|
| 水下 | 其余全部 | U = 1 − max(A, 0.8·W) | 水下床、从下方听到的水面翻涌（A02，闷）、水流、鲸鸣、生物声 | 海鸥、风、空气中的浪声、空气中的喷气 |
| 空中（高空俯视，约 200 米） | 0.1545–0.195（A 由 `surface.aerial` 给出：0.150→0.159 升到 1，0.190→0.199 降到 0） | A | 远处成片的海浪、微风、海鸥、远处的喷气（有约 0.58 秒声音延迟） | 任何水下的声音、鲸鸣、拍尾 |
| 水线中景（半水上半水下） | 0.199–0.2185（W：0.193→0.199 升到 1，0.2178→0.2192 降到 0） | W | 以空气声为主：近处拍打鲸背的水声、喷气与吸气；水下床压低到约 −14 dB 作为“下半画面”的底 | 鲸鸣、深海床 |

**穿越水面的转场**（与画面的水线对齐，误差 ≤ 100 ms）：

- **出水**（p 0.150–0.159，水线在 p ≈ 0.1545 扫过画面中央）：之前 1.5 秒水下床变亮、A02 变响（接近水面）；穿越时刻由 F06 的“破水”承担；水下层在 0.4 秒内等功率交叉淡出，同时其低通从当前值扫到 400 Hz；空气层从 0.1545 起淡入。
- **高空 → 水线**（p 0.190–0.199）：F13 浪花水雾从镜头前涌过，A04 交叉淡入 A05。
- **入水**（p 0.218–0.2195，相机在 p ≈ 0.2185 穿过水面）：F14 入水；空气层 0.3 秒内淡出；水下床淡入，其低通在穿越后 1 秒内从 1200 Hz 打开到 4000 Hz（“耳朵在水下张开”）。

**规则**：属于某一视角的一次性音效，如果在播放中视角被翻转（例如用户倒退回水下），0.3 秒淡出。

### 1.6 深度对音色的影响

| 深度 d | 区域 | 水下床 | 低通（水下层） | 其他 |
|---|---|---|---|---|
| 0–50 m | 透光层（开场、闭眼、下沉开始、新鲸鱼） | A01 开阔水下 −27；A02 水面翻涌按深度 | 5000 → 3200 Hz | 有阳光的海：明亮、柔和的嘶声与缓慢起伏 |
| 50–250 m | 透光层下部 | A01 渐弱 | 3200 → 1500 Hz | 水面翻涌在 45 m 以下消失 |
| 250–1000 m | 弱光层 | A03 深海床 −32 | 1600 → 900 Hz | 合唱最清楚（深海声道，低频传得远），约 600–1200 m 处 |
| 1000–1800 m | 无光层、海床 | A03 −32 → −34 | 900 → 650 Hz | 只有零星的生物声；没有“闪光”音效（生物发光是无声的） |

深度曲线见 2.1 的表；必须保留 300–800 Hz 的“底”，否则手机外放在深海段会变成一片死寂（深海可以安静，但不能“像坏了”）。

### 1.7 播放状态下的行为

| 状态 | 连续层（床、水流、纹理） | 一次性音效 | 鲸鸣 |
|---|---|---|---|
| 正向自动播放 | 跟随 p（增益平滑 τ ≈ 0.25 s） | 越过触发点时触发一次 | 同左，另按 4.3 避开旁白 |
| 暂停 | 保持当前值，整体 −6 dB（1 s 渐变）；继续播放时 0.6 s 恢复 | 正在响的自然播完，不切断；不触发新的 | 同左 |
| 倒放 / 向上滚动回看 | 跟随 p（素材本身仍正向播放，只是电平随 p 变） | **不触发**；倒退越过某个正在响的音效的触发点时 0.3 s 淡出 | 倒退越过触发点时 1 s 淡出 |
| 手动向前滚动（含暂停时滚动） | 跟随 p | 按速度比 r = 实际速度 / 该段自动播放速度：r ≤ 1.6 正常触发；1.6 < r ≤ 3.5 只触发主角音效（V、F03、F06、F11、F14、F15 主击）；r > 3.5 全部跳过；任何情况下主角音效之间至少间隔 2 秒真实时间 | 只在 r ≤ 1.6 时触发 |
| 跳章节 / 重新开始 / 进出自由探索（画面 0.9 s 溶解） | 0.9 s 交叉渐变到新 p 的状态 | 不触发；正在响的 0.5 s 淡出 | 不触发 |
| 循环接缝 p 0.999 → 0.000 | 所有连续层在接缝两侧取值与斜率一致（见 2.12）；**循环素材绝不在 p=0 重新开始播放** | 用**累计进度**（`StoryProgressController.shown`，含圈数）判断越过，接缝不丢 cue；区间 [0.985, 1) ∪ [0, 0.006) 内不安排任何一次性音效 | 同左 |
| 自由探索 | 见 2.13 | 不触发叙事 cue | 每 100–160 秒一声极远的鲸鸣（按序号轮换，不随机） |
| 开场界面（点击开始之前） | 无声（音频尚未解锁） | — | — |
| 第一次开始 | 所有床从静音 2.5 s 淡入 | p 0.006 之前没有 cue | — |
| 静音（M 键 / 按钮 / `?muted`） | 主增益 0.25 s 归零（含旁白） | — | — |
| 页面进入后台 | 挂起 AudioContext；回来时直接设到当前目标值，不从旧值渐变 | 不补发 | 不补发 |

一次性音效以 `AudioContext.currentTime` 精确排程（同一帧内越过的 cue 按 p 的先后排序，起点差按秒换算），不用 `setTimeout`。

### 3.3 处理与交付规范

- **格式**：MP3（CBR，LAME），44.1 kHz；床与一次性音效默认单声道 64 kbps；A04、A05、F11 用立体声（96–128 kbps）；A03、F16 等低通在 4 kHz 以下的素材可用 32 kHz / 48 kbps。
- **无缝循环**：MP3 编码会在首尾加入填充，不能直接首尾相接。每个循环文件前后各多留 0.2 s，在 `manifest.json` 里写明循环区间（例如 `"loop": [0.2, 30.2]`），代码用 `loopStart / loopEnd`。循环体在离线时用 2–3 s 交叉淡化做成无缝。每个循环素材里不能有容易被记住的单个事件（一声鸥叫、一下拍水），否则一听就知道在循环。
- **归一化**：循环床 −18 LUFS（积分），一次性音效与鲸鸣 −18 LUFS（短时最大值）；真峰值 ≤ −1 dBTP；一次性音效首尾 5–20 ms 淡化，不得有咔嗒。
- **视角烤入**：水下素材离线做好低通与水下的“闷”；远近（尾巴长短、亮度）也离线做好；运行时只做增益、深度相关的低通、少量声像。
- **单声道兼容**：竖屏手机基本是单声道外放，所有立体声素材折叠成单声道后不能有相位抵消。
- **命名**：`<编号>_<英文名>.mp3`，例如 `A01_uw-open.mp3`、`F11_blow-near.mp3`、`V03_call-b-far.mp3`；manifest 的键用编号。
- **生成脚本**：所有处理写成可重跑的脚本（参照 `scripts/whale-audio.py` 的风格），放在 `scripts/`；原始下载放在不提交的目录里。

### 4.3 旁白压低（ducking）规则

| 母线 / 对象 | 旁白说话时 | 说明 |
|---|---|---|
| BED（全部床） | −7 dB | 其中空气中的海浪 A04、A05 −9 dB，并在 2.5 kHz 加一个 −3 dB、Q 0.8 的峰值衰减（浪声的嘶嘶与辅音同频） |
| SFX 普通音效 | −5 dB | |
| SFX 主角音效（F03、F06、F11、F14、F15 主击、F17 咬合与 F18 撕下） | −2 dB | F11 喷气与 F15 着地主击在开始后的前 1.2 s 不压低 |
| BIO 鲸鸣 | −8 dB | 鲸鸣按排程本来就避开旁白，这只是重叠尾巴时的保护 |
| BIO 海鸥 / 抹香鲸 | −8 / −10 dB | |
| UI | 不压低 | |

- **起落时间**：起（压下去）0.25 s，**提前 0.15 s 开始**（旁白系统通过 `nextStartIn` 预告下一句）；落（恢复）1.0 s，在人声结束 0.4 s 后开始；两句之间间隔小于 2.0 s 时保持压低，不来回“呼吸”。
- **鲸鸣的等待规则**：鲸鸣 cue 到达时如果旁白正在说话，进入等待；旁白结束 0.5 s 后播放；若等到表中的“最晚 p”旁白仍在说话，就以 −8 dB 播放。等待期间如果用户倒退或跳转，取消。
- **新一句旁白开始前 0.5 s 内**不启动新的普通一次性音效（主角音效不受此限）；已经在响的不受影响。
- 旁白关闭：不压低，等待规则失效（鲸鸣按原 p 触发）。
- 旁白暂停（用户暂停）：压低在 1.0 s 内恢复。

### 4.4 同时发声与性能

- 同时活动的音源节点 ≤ 16；一次性音效同一编号最多同时 2 个（拍尾第三个出现时淡出最早的）。
- 连续层的增益与滤波用 `setTargetAtTime`（τ 0.25 s，跳转时 τ 0.3 s 配合 0.9 s 溶解），不要每帧 `setValueAtTime` 产生拉链噪声。

### 4.5 体积预算与按需加载

## 5. 验收清单（审听者逐条打勾）

**删除与结构**

**逐段审听（正向自动播放一整圈，手机外放 + 耳机各一遍）**

- [ ] 开场：先只有海，再有身体的水流与拍尾，再有第一声鲸鸣（p ≈ 0.036，身体从头顶经过时），再有磷虾的窸窣；没有任何“咚咚”像鼓或心跳的声音。

- [ ] 出水：“哗”与水线扫过画面中央对齐（≤ 100 ms）；高空镜头里**没有任何水下的声音**；海鸥只在高空镜头里，零星几声，不像港口。
